# 0010 練習環境の構築

このリポジトリの Terraform で、private-isu 用 EC2 を AWS 上に立てます。

- 立てたら、番号の順に進みます。
- 0015〜0100 は、1 台に全部入った構成でチューニングします。
- 最後の [0110-split-1.md](0110-split-1.md) で、役割を分けます。

?> `c7a.large` は起動中ずっと課金されます。中断するときは停止し、不要なら `terraform destroy` します。

`terraform` コマンドは、`terraform/` で実行します。

## 1. Terraform を入れる（二択。初回のみ）

- CloudShell から用意するなら 1-a。
- 手元のパソコンから用意するなら 1-b。
- どちらも、2 回目以降は不要です。

<a id="1-a-cloudshell-を使う"></a>

### 1-a. CloudShell を使う

- CloudShell（ブラウザ上で動く AWS のターミナル）のホームは、消えずに残ります。
- 2 回目以降は、1-a を飛ばします。

```bash
cd /tmp
git clone --depth=1 https://github.com/tfutils/tfenv.git ~/.tfenv
mkdir -p ~/bin
ln -sf ~/.tfenv/bin/* ~/bin/
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
echo 'export TF_DATA_DIR=/tmp/.terraform' >> ~/.bashrc
source ~/.bashrc

tfenv install latest
tfenv use latest
terraform -version
echo "$TF_DATA_DIR"   # /tmp/.terraform であること
```

- `TF_DATA_DIR` は、Terraform の部品（プロバイダ）を置く場所の指定です。
- CloudShell に使える保存領域は 1 GB しかありません。使い切らないように、`/tmp` にします。
- `/tmp` は、セッションが切れると空になります。
- 開き直したら、`terraform init` をやり直します。
- Terraform の作成記録（state）は S3 に保存されます。

<a id="1-b-ローカルから-aws-login-でデプロイする"></a>

### 1-b. ローカルから `aws login` でデプロイする

- `aws login` は、AWS CLI v2 でないと使えません。

```bash
# AWS CLI v2 でなければ先に v2 を入れる
aws --version

aws login

# アカウントIDが取得できることを確認
aws sts get-caller-identity --query Account --output text

# S3 state を使うため terraform は 1.10 以上にします
mise install terraform@latest
mise use -g terraform@latest
terraform -version
```

## 3. state 用 S3 バケット（初回のみ）

- 本編の EC2 とは別に、コマンドで先に作ります。
- `tfvars`（設定ファイル）では指定できません。


| 接頭辞      | バケット名                                  |
| -------- | -------------------------------------- |
| なし       | `private-isu-tfstate-<アカウントID>`        |
| `myname` | `myname-private-isu-tfstate-<アカウントID>` |


- 接頭辞は、英小文字・数字・ハイフンで書きます。
- 同じアカウントを複数人で使うときだけ、付けます。

```bash
# S3Bucketに接頭辞を付ける。無しなら空でよい
PREFIX=''

## ここから下はコピペでOK
REGION=ap-northeast-1
ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
if [ -n "$PREFIX" ]; then
  BUCKET="${PREFIX}-private-isu-tfstate-${ACCOUNT_ID}"
else
  BUCKET="private-isu-tfstate-${ACCOUNT_ID}"
fi
echo "bucket=$BUCKET"

if aws s3api head-bucket --bucket "$BUCKET" 2>/dev/null; then
  echo "already exists"
else
  aws s3api list-buckets \
    --query "Buckets[?contains(Name, 'private-isu-tfstate')].Name" --output table

  aws s3api create-bucket --bucket "$BUCKET" --region "$REGION" \
    --create-bucket-configuration "LocationConstraint=${REGION}"
  aws s3api put-bucket-versioning --bucket "$BUCKET" \
    --versioning-configuration Status=Enabled
  aws s3api put-public-access-block --bucket "$BUCKET" \
    --public-access-block-configuration \
    BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
  aws s3api put-bucket-encryption --bucket "$BUCKET" \
    --server-side-encryption-configuration \
    '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"},"BucketKeyEnabled":true}]}'
fi

cd /tmp/private-isu-terraform/terraform
cat > backend.hcl <<EOF
bucket = "${BUCKET}"
EOF
```

- `backend.hcl` は、git に入れません。
- 既に存在するバケットに繋ぐだけなら、作成を飛ばして名前を書けば十分です。
- 本編を `destroy` しても、バケットは残ります。
- 不要なら、コンソールか `aws s3 rb` で消します（中の state も消えます）。

## 4. terraform.tfvars

```bash
cd /tmp/private-isu-terraform/terraform
cp terraform.tfvars.example terraform.tfvars
```

- `allowed_cidrs` には、自分のグローバル IP を書きます。
- ブラウザで [https://checkip.amazonaws.com](https://checkip.amazonaws.com) を開いて、確認します。
- CloudShell で `curl` すると、CloudShell の IP になります（確認はブラウザで行います）。

```bash
# ブラウザで確認した値
MY_IP='60.114.21.85'

# コピペでOK
sed -i "s|203\.0\.113\.1/32|${MY_IP}/32|" terraform.tfvars
cat terraform.tfvars
```

- `vi terraform.tfvars` でも編集できます。
- このファイルは、git に入れません。

### 台数（1 台か 3 台か）

- ここだけが、1 台と複数台の違いです。
- example の既定は `3` です。
- 役割は、Terraform では決めません。
- **0015〜0100 は、1 台に全部入った構成で進めます。**
- [0110-split-1.md](0110-split-1.md) で分けるまでに、3 台にします。


| 構成  | 書く値 | 起動直後                         | このあと                                                                                       |
| --- | --- | ---------------------------- | ------------------------------------------------------------------------------------------ |
| 1 台から始める | `1` | nginx + アプリ + MySQL が同じ台に全部入った状態 | 初動 [0010-setup.md](../010_common/0010-setup.md) → 0015〜0100 を 1 台で → 0110 の分割までに `3` へ増やす |
| 3 台を用意する | `3` | 各台とも同じく全部入った状態                   | 1 台目（s1）で 0015〜0100 → 役割分割 [0110-split-1.md](0110-split-1.md)             |


- `terraform.tfvars` には、どちらか一方を書きます。
- 1 台にするときは、example の `3` を上書きします。
- あとから `3` に書き換えて apply すると、2 台増えます。
- 増えたあとは、作業した台を s1 にします。

```hcl
# 1 台
webapp_instance_count = 1

# 複数台（example の既定）
# webapp_instance_count = 3
```

## 5. 構築

```bash
cd /tmp/private-isu-terraform/terraform

# TF_DATA_DIR は CloudShell 経路（1-a）だけが設定します。
# ローカル（1-b）から進めた場合、空のままでも init は通ります（既定の .terraform/ を使う）。
# 空でも異常ではありません（下の備考参照）。
source ~/.bashrc 2>/dev/null || true
echo "TF_DATA_DIR=${TF_DATA_DIR:-(未設定 → 既定の .terraform/ を使う)}"

terraform init -backend-config=backend.hcl
terraform plan
terraform apply
```

- **apply 直後は、80 番がまだ開いていません。**
- AMI の起動（Ruby / MySQL / nginx の初期化）に、1〜2 分かかります。
- 直後に確認すると、失敗したように見えることがあります。
- **`terraform output` が出たら、1〜2 分待ちます。**
- それから、ブラウザで確認します。

```text
Failed to connect to 52.194.189.184 port 80 after 11191 ms: Could not connect to server
Failed to connect to 3.112.34.221 port 80 after 8 ms: Could not connect to server
```

- 数分後に同じコマンドで 200 が返れば、正常です。

以前は state を手元（ローカル）に置いていた場合の初回だけ:

```bash
terraform init -backend-config=backend.hcl -migrate-state
```

- `webapp_url`（1 台目）をブラウザで開きます。
- Iscogram が出れば、完了です。
- 全台の一覧は、`webapp_urls` / `webapp_public_ips` です。
- 起動直後は、どの台も 1 台に全部入った構成です。

## 6. SSM でログインする

- サーバーに入る手段は、どちらの方法でも SSM（AWS が用意する接続機能。ブラウザや AWS CLI から入れます）です。
- SSH（`enable_ssh` / キーペア）は要りません。

```bash
# ローカルの場合は 1-b の `aws login` を済ませておきます
# 出てきたコマンドをそのまま打つ
terraform output ssm_login_commands
```

- 入ったら、`isucon` に切り替えます。

```bash
sudo su - isucon
```

## 7. ベンチを 1 本回す

- 起動直後は、どの台も 1 台に全部入った構成（nginx + Ruby + MySQL）です。
- **どの台に入れても、`-t http://localhost` で動きます。**
- 3 台にした段階でも、s1・s2・s3 のどれでも同じです。

```bash
# webアプリ実行ユーザである isucon で打つ
sudo su - isucon

/home/isucon/private_isu/benchmarker/bin/benchmarker \
  -u /home/isucon/private_isu/benchmarker/userdata \
  -t http://localhost
```

#### 実行例：

2026-10-13、`c7a.large` 1 台 / `ap-northeast-1` / 起動直後の Ruby オールインワン（索引無し・アプリ素体）（nginx + Ruby + MySQL が同じ台）/ `nproc=2` / メモリ 3.7Gi の状態です。

```text
$ sudo -iu isucon /home/isucon/private_isu/benchmarker/bin/benchmarker \
    -u /home/isucon/private_isu/benchmarker/userdata \
    -t http://localhost
{"pass":true,"score":936,"success":799,"fail":0,"messages":[]}
```

| 環境 | score | pass | fail |
| --- | --- | --- | --- |
| `c7a.large` × 1 / `nproc=2` / メモリ 3.7Gi / 起動直後の Ruby オールインワン（索引無し・アプリ素体） | 936 | true | 0 |

- 条件（索引の有無など）で、`score` の桁が変わります。
- 同じ条件でも、数百〜数千点動きます。
- `fail` が 0 であることを確認してから、次へ進みます。

- ここが、この章の出口です。次は [0015-sql-tuning.md](0015-sql-tuning.md) で SQL の調整をします。
- 役割を分けたあとは、ベンチを nginx 役の s1 に打ちます（[0110-split-3.md](0110-split-3.md) §11）。

## 8. 停止・削除

```bash
# 中断（EBS 課金は残る）。1 台でも 3 台でも全台
aws ec2 stop-instances --instance-ids $(terraform output -json webapp_instance_ids | jq -r '.[]')

# 再開
aws ec2 start-instances --instance-ids $(terraform output -json webapp_instance_ids | jq -r '.[]')

# パブリック IP は変わる
terraform apply -refresh-only
terraform output webapp_urls
```

不要になったら:

```bash
terraform destroy
```

- AMI には、セキュリティ更新が入りません。
- 長期間、起動したままにしません。

| 期間 | 対応 |
| --- | --- |
| 数日〜数週間 | インスタンス停止（EBS のみ課金） |
| しばらく使わない | `terraform destroy` |

## 備考

### CloudShell のホームが消えたとき

```bash
source ~/.bashrc
echo "$TF_DATA_DIR"
cd /tmp
git clone https://github.com/k-hoshihara/private-isu-terraform.git
cd private-isu-terraform

REGION=ap-northeast-1
PREFIX=                         # 初回と同じ
ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
if [ -n "$PREFIX" ]; then
  BUCKET="${PREFIX}-private-isu-tfstate-${ACCOUNT_ID}"
else
  BUCKET="private-isu-tfstate-${ACCOUNT_ID}"
fi
cd terraform
printf 'bucket = "%s"\n' "$BUCKET" > backend.hcl
cp terraform.tfvars.example terraform.tfvars
# allowed_cidrs を書く。destroy だけなら任意の /32 でよい
# 台数は初回と同じ（1 台なら 1、複数台なら 3）

terraform init -backend-config=backend.hcl
terraform destroy
```

- state バケットは、`destroy` では消えません。

### `echo "$TF_DATA_DIR"` が空 / no space left on device

- **空でも、異常ではありません。**
- `TF_DATA_DIR` は、CloudShell 経路（[1-a](#1-a-cloudshell-を使う)）だけが設定します。
- 手元のパソコン（[1-b](#1-b-ローカルから-aws-login-でデプロイする)）から進めた場合、空のままで動きます。
- その場合の `terraform init` は、既定の `terraform/.terraform/` を使います。

```bash
# 空なら 1-b から進めたので、そのままでよい
echo "TF_DATA_DIR=${TF_DATA_DIR:-(未設定)}"

# no space left on device のときだけ、書きかけの .terraform を消してやり直す
rm -rf terraform/.terraform
cd terraform && terraform init -backend-config=backend.hcl
```

### `head-bucket` や `create-bucket` が失敗する

- 権限・リージョン・バケット名の衝突を見ます。
- 同じアカウントに、別名の `*-private-isu-tfstate-*` が無いか `list-buckets` で確認します。
- 接頭辞を変えると、別バケットになります。古い state は見えません。

### `TargetNotConnected`

- インスタンス起動直後です。
- 1〜2 分待って、SSM をやり直します。

```bash
aws ssm start-session --target $(terraform output -raw webapp_instance_id)
```

### `webapp_url` が古い

- 停止して起動すると、パブリック IP が変わります。
- 全台の一覧は、`webapp_urls` です。

```bash
terraform apply -refresh-only
terraform output webapp_urls
```

# 0010 練習環境の構築

このリポジトリの Terraform で、private-isu 用 EC2 を AWS 上に立てる手順です。

> \[!WARNING\]
> `c7a.large` は起動中ずっと課金される。中断するときは停止、不要なら `terraform destroy`。

特に断りのない `terraform` は `terraform/` で実行する。

## 1. Terraform を入れる（CloudShellを使ったデプロイ版：初回のみ）

ホームは永続化されるので、次回のセッションでは不要。

```bash
cd /tmp
git clone --depth=1 https://github.com/tfutils/tfenv.git ~/.tfenv
mkdir -p ~/bin
ln -sf ~/.tfenv/bin/* ~/bin/
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
echo 'export TF_DATA_DIR=/tmp/.terraform' >> ~/.bashrc
source ~/.bashrc

tfenv install latest
tfenv use latest
terraform -version
echo "$TF_DATA_DIR"   # /tmp/.terraform であること
```

`TF_DATA_DIR` はプロバイダバイナリの置き場。Linux 版 AWS プロバイダは約 850MB あり、CloudShell の永続領域（1GB）を食い潰す。`/tmp` なら消えてもよい。

`/tmp` はセッション切れで空になる。開き直したら `terraform init` をやり直す。state は S3 にある。

## 3. state 用 S3 バケット（初回のみ）

本編の EC2 とは別に、CLI で先に作る。`tfvars` では指定できない。


| 接頭辞      | バケット名                                  |
| -------- | -------------------------------------- |
| なし       | `private-isu-tfstate-<アカウントID>`        |
| `myname` | `myname-private-isu-tfstate-<アカウントID>` |


接頭辞は英小文字・数字・ハイフン。同じアカウントを複数人で使うときだけ付ける。

```bash
# S3Bucketに接頭辞を付ける。無しなら空でよい
PREFIX=''

## ここから下はコピペでOK
REGION=ap-northeast-1
ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
if [ -n "$PREFIX" ]; then
  BUCKET="${PREFIX}-private-isu-tfstate-${ACCOUNT_ID}"
else
  BUCKET="private-isu-tfstate-${ACCOUNT_ID}"
fi
echo "bucket=$BUCKET"

if aws s3api head-bucket --bucket "$BUCKET" 2>/dev/null; then
  echo "already exists"
else
  aws s3api list-buckets \
    --query "Buckets[?contains(Name, 'private-isu-tfstate')].Name" --output table

  aws s3api create-bucket --bucket "$BUCKET" --region "$REGION" \
    --create-bucket-configuration "LocationConstraint=${REGION}"
  aws s3api put-bucket-versioning --bucket "$BUCKET" \
    --versioning-configuration Status=Enabled
  aws s3api put-public-access-block --bucket "$BUCKET" \
    --public-access-block-configuration \
    BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
  aws s3api put-bucket-encryption --bucket "$BUCKET" \
    --server-side-encryption-configuration \
    '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"},"BucketKeyEnabled":true}]}'
fi

cd /tmp/private-isu-terraform/terraform
cat > backend.hcl <<EOF
bucket = "${BUCKET}"
EOF
```

`backend.hcl` は git に入れない。既存バケットへ繋ぐだけなら、作成を飛ばして名前だけ書けばよい。  
本編を `destroy` してもバケットは残る。不要ならコンソールまたは `aws s3 rb`（中の state も消える）。

## 4. terraform.tfvars

```bash
cd /tmp/private-isu-terraform/terraform
cp terraform.tfvars.example terraform.tfvars
```

`allowed_cidrs` は自分のグローバル IP。ブラウザで [https://checkip.amazonaws.com](https://checkip.amazonaws.com) を開く。  
CloudShell で `curl` すると CloudShell の IP になる。

```bash
# ブラウザで確認した値
MY_IP='60.114.21.85'

# コピペでOK
sed -i "s|203\.0\.113\.1/32|${MY_IP}/32|" terraform.tfvars
cat terraform.tfvars
```

`vi terraform.tfvars` でもよい。このファイルは git に入れない。

### 台数（1 台か 3 台か）

ここだけが 1 台と複数台の違い。example の既定は `3`。役割は Terraform では固定しない。


| 構成  | 書く値 | 起動直後                         | このあと                                                                                       |
| --- | --- | ---------------------------- | ------------------------------------------------------------------------------------------ |
| 1 台 | `1` | nginx + アプリ + MySQL のオールインワン | 初動 [0010-setup.md](../010_common/0010-setup.md) → 計測ドリル [0030-measure.md](0030-measure.md) |
| 複数台 | `3` | 各台がオールインワン                   | 役割分割は [0020-split.md](0020-split.md)                                                       |


`terraform.tfvars` にどちらか一方を書く。1 台にするときは example の `3` を上書きする。

```hcl
# 1 台
webapp_instance_count = 1

# 複数台（example の既定）
# webapp_instance_count = 3
```

## 5. 構築

```bash
cd /tmp/private-isu-terraform/terraform
source ~/.bashrc
echo "$TF_DATA_DIR"

terraform init -backend-config=backend.hcl
terraform plan
terraform apply
```

以前ローカル state だった場合の初回だけ:

```bash
terraform init -backend-config=backend.hcl -migrate-state
```

`webapp_url`（1 台目）をブラウザで開き、Iscogram が出れば完了。全台は `webapp_urls` / `webapp_public_ips`。起動直後は各台がオールインワン。

## 8. 停止・削除

```bash
# 中断（EBS 課金は残る）。1 台でも 3 台でも全台
aws ec2 stop-instances --instance-ids $(terraform output -json webapp_instance_ids | jq -r '.[]')

# 再開
aws ec2 start-instances --instance-ids $(terraform output -json webapp_instance_ids | jq -r '.[]')

# パブリック IP は変わる
terraform apply -refresh-only
terraform output webapp_urls
```

不要になったら:

```bash
terraform destroy
```

AMI にセキュリティ更新は入らない。長期間つけっぱなしにしない。

| 期間       | 対応                  |
| -------- | ------------------- |
| 数日〜数週間   | インスタンス停止。EBS のみ課金   |
| しばらく使わない | `terraform destroy` |


state バケットは `destroy` では消えない。



### `echo "$TF_DATA_DIR"` が空 / no space left on device

`~/.bashrc` に書いていないか、`source` していない。書きかけの `.terraform` を消してからやり直す。

```bash
rm -rf terraform/.terraform
source ~/.bashrc
echo "$TF_DATA_DIR"
cd terraform && terraform init -backend-config=backend.hcl
```

### `head-bucket` や `create-bucket` が失敗する

権限、リージョン、バケット名の衝突を見る。同じアカウントに別名の `*-private-isu-tfstate-*` が無いか `list-buckets` する。接頭辞を変えると別バケットになり、古い state は見えない。

### `TargetNotConnected`

インスタンス起動直後。1〜2 分待って SSM をやり直す。

```bash
aws ssm start-session --target $(terraform output -raw webapp_instance_id)
```

### `webapp_url` が古い

停止して起動するとパブリック IP が変わる。全台は `webapp_urls`。

```bash
terraform apply -refresh-only
terraform output webapp_urls
```

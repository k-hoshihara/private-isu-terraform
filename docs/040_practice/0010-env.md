# 0010 練習環境の構築

このリポジトリの Terraform で、private-isu 用 EC2 を AWS 上に立てる手順です。立てたら次へ進みます。1 台なら [0010-setup.md](../010_common/0010-setup.md) → [0030-measure.md](0030-measure.md)、複数台なら [0020-split-1.md](0020-split-1.md) です。番号順に地続きになっています。

?> `c7a.large` は起動中ずっと課金されます。中断するときは停止し、不要なら `terraform destroy` します。

特に断りのない `terraform` は `terraform/` で実行します。

## 1. Terraform を入れる（二択。初回のみ）

CloudShell からのデプロイなら 1-a、ローカルからなら 1-b を使います。どちらも 2 回目以降は不要です。

### 1-a. CloudShell を使う

CloudShell のホームは永続化されます。2 回目以降は 1-a を飛ばします。

```bash
cd /tmp
git clone --depth=1 https://github.com/tfutils/tfenv.git ~/.tfenv
mkdir -p ~/bin
ln -sf ~/.tfenv/bin/* ~/bin/
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
echo 'export TF_DATA_DIR=/tmp/.terraform' >> ~/.bashrc
source ~/.bashrc

tfenv install latest
tfenv use latest
terraform -version
echo "$TF_DATA_DIR"   # /tmp/.terraform であること
```

`TF_DATA_DIR` はプロバイダバイナリの置き場です。CloudShell の永続領域（1 GB）を食い潰さないため `/tmp` にします。

`/tmp` はセッション切れで空になります。開き直したら `terraform init` をやり直します。state は S3 にあります。

### 1-b. ローカルから `aws login` でデプロイする

`aws login` は AWS CLI v2 でないと使えません。

```bash
# AWS CLI v2 でなければ先に v2 を入れる
aws --version

aws login

# アカウントIDが取得できることを確認
aws sts get-caller-identity --query Account --output text

# S3 state を使うため terraform は 1.10 以上にします
mise install terraform@latest
mise use -g terraform@latest
terraform -version
```

## 2. リポジトリを取る

```bash
cd /tmp
git clone https://github.com/k-hoshihara/private-isu-terraform.git
# ブランチを変えたい場合はこちら
# BRANCH_NAME='develop/XXX'
# git clone -b ${BRANCH_NAME} https://github.com/k-hoshihara/private-isu-terraform.git

cd private-isu-terraform
```

## 3. state 用 S3 バケット（初回のみ）

本編の EC2 とは別に、CLI で先に作ります。`tfvars` では指定できません。


| 接頭辞      | バケット名                                  |
| -------- | -------------------------------------- |
| なし       | `private-isu-tfstate-<アカウントID>`        |
| `myname` | `myname-private-isu-tfstate-<アカウントID>` |


接頭辞は英小文字・数字・ハイフンです。同じアカウントを複数人で使うときだけ付けます。

```bash
# S3Bucketに接頭辞を付ける。無しなら空でよい
PREFIX=''

## ここから下はコピペでOK
REGION=ap-northeast-1
ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
if [ -n "$PREFIX" ]; then
  BUCKET="${PREFIX}-private-isu-tfstate-${ACCOUNT_ID}"
else
  BUCKET="private-isu-tfstate-${ACCOUNT_ID}"
fi
echo "bucket=$BUCKET"

if aws s3api head-bucket --bucket "$BUCKET" 2>/dev/null; then
  echo "already exists"
else
  aws s3api list-buckets \
    --query "Buckets[?contains(Name, 'private-isu-tfstate')].Name" --output table

  aws s3api create-bucket --bucket "$BUCKET" --region "$REGION" \
    --create-bucket-configuration "LocationConstraint=${REGION}"
  aws s3api put-bucket-versioning --bucket "$BUCKET" \
    --versioning-configuration Status=Enabled
  aws s3api put-public-access-block --bucket "$BUCKET" \
    --public-access-block-configuration \
    BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
  aws s3api put-bucket-encryption --bucket "$BUCKET" \
    --server-side-encryption-configuration \
    '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"},"BucketKeyEnabled":true}]}'
fi

cd /tmp/private-isu-terraform/terraform
cat > backend.hcl <<EOF
bucket = "${BUCKET}"
EOF
```

`backend.hcl` は git に入れません。既存バケットへ繋ぐだけなら、作成を飛ばして名前だけ書けばよいです。
本編を `destroy` してもバケットは残ります。不要ならコンソールまたは `aws s3 rb` で消します（中の state も消えます）。

## 4. terraform.tfvars

```bash
cd /tmp/private-isu-terraform/terraform
cp terraform.tfvars.example terraform.tfvars
```

`allowed_cidrs` は自分のグローバル IP です。ブラウザで [https://checkip.amazonaws.com](https://checkip.amazonaws.com) を開きます（CloudShell で `curl` すると CloudShell の IP になります）。

```bash
# ブラウザで確認した値
MY_IP='60.114.21.85'

# コピペでOK
sed -i "s|203\.0\.113\.1/32|${MY_IP}/32|" terraform.tfvars
cat terraform.tfvars
```

`vi terraform.tfvars` でもよいです。このファイルは git に入れません。

### 台数（1 台か 3 台か）

ここだけが 1 台と複数台の違いです。example の既定は `3` です。役割は Terraform では固定しません。


| 構成  | 書く値 | 起動直後                         | このあと                                                                                       |
| --- | --- | ---------------------------- | ------------------------------------------------------------------------------------------ |
| 1 台 | `1` | nginx + アプリ + MySQL のオールインワン | 初動 [0010-setup.md](../010_common/0010-setup.md) → 計測ドリル [0030-measure.md](0030-measure.md) |
| 複数台 | `3` | 各台がオールインワン                   | 役割分割は [0020-split-1.md](0020-split-1.md)                                                       |


`terraform.tfvars` にどちらか一方を書きます。1 台にするときは example の `3` を上書きします。

```hcl
# 1 台
webapp_instance_count = 1

# 複数台（example の既定）
# webapp_instance_count = 3
```

## 5. 構築

```bash
cd /tmp/private-isu-terraform/terraform
source ~/.bashrc
echo "$TF_DATA_DIR"

terraform init -backend-config=backend.hcl
terraform plan
terraform apply
```

以前ローカル state だった場合の初回だけ:

```bash
terraform init -backend-config=backend.hcl -migrate-state
```

`webapp_url`（1 台目）をブラウザで開きます。Iscogram が出れば完了です。全台は `webapp_urls` / `webapp_public_ips` です。起動直後は各台がオールインワンです。

## 6. SSM でログインする

どちらから実行した場合も、入口は SSM です。SSH（`enable_ssh` / キーペア）は要りません。

```bash
# ローカルの場合は 1-b の `aws login` を済ませておきます
# 出てきたコマンドをそのまま打つ
terraform output ssm_login_commands
```

入ったら `isucon` に切り替えます。

```bash
sudo su - isucon
```

## 7. ベンチを 1 本回す

分割前は 1 台構成なので、同じホストの `localhost` を `-t` にします。複数台に分けたあとは nginx 役の s1 に入れます（[0020-split-1.md](0020-split-1.md)）。

```bash
# webアプリ実行ユーザである isucon で打つ
sudo su - isucon

/home/isucon/private_isu/benchmarker/bin/benchmarker \
  -u /home/isucon/private_isu/benchmarker/userdata \
  -t http://localhost
```

## 8. 停止・削除

```bash
# 中断（EBS 課金は残る）。1 台でも 3 台でも全台
aws ec2 stop-instances --instance-ids $(terraform output -json webapp_instance_ids | jq -r '.[]')

# 再開
aws ec2 start-instances --instance-ids $(terraform output -json webapp_instance_ids | jq -r '.[]')

# パブリック IP は変わる
terraform apply -refresh-only
terraform output webapp_urls
```

不要になったら:

```bash
terraform destroy
```

AMI はセキュリティ更新が入りません。長期間起動したままにしません。

| 期間 | 対応 |
| --- | --- |
| 数日〜数週間 | インスタンス停止（EBS のみ課金） |
| しばらく使わない | `terraform destroy` |

## 備考

### CloudShell のホームが消えたとき

```bash
source ~/.bashrc
echo "$TF_DATA_DIR"
cd /tmp
git clone https://github.com/k-hoshihara/private-isu-terraform.git
cd private-isu-terraform

REGION=ap-northeast-1
PREFIX=                         # 初回と同じ
ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
if [ -n "$PREFIX" ]; then
  BUCKET="${PREFIX}-private-isu-tfstate-${ACCOUNT_ID}"
else
  BUCKET="private-isu-tfstate-${ACCOUNT_ID}"
fi
cd terraform
printf 'bucket = "%s"\n' "$BUCKET" > backend.hcl
cp terraform.tfvars.example terraform.tfvars
# allowed_cidrs を書く。destroy だけなら任意の /32 でよい
# 台数は初回と同じ（1 台なら 1、複数台なら 3）

terraform init -backend-config=backend.hcl
terraform destroy
```

state バケットは `destroy` では消えません。

### `echo "$TF_DATA_DIR"` が空 / no space left on device

`~/.bashrc` に書いていないか、`source` していないか確認します。書きかけの `.terraform` を消してからやり直します。

```bash
rm -rf terraform/.terraform
source ~/.bashrc
echo "$TF_DATA_DIR"
cd terraform && terraform init -backend-config=backend.hcl
```

### `head-bucket` や `create-bucket` が失敗する

権限、リージョン、バケット名の衝突を見ます。同じアカウントに別名の `*-private-isu-tfstate-*` が無いか `list-buckets` します。接頭辞を変えると別バケットになり、古い state は見えません。

### `TargetNotConnected`

インスタンス起動直後です。1〜2 分待って SSM をやり直します。

```bash
aws ssm start-session --target $(terraform output -raw webapp_instance_id)
```

### `webapp_url` が古い

停止して起動するとパブリック IP が変わります。全台は `webapp_urls` です。

```bash
terraform apply -refresh-only
terraform output webapp_urls
```

# 0020 複数台に分割する（中盤:分割実装）



## 8. nginx / アプリ / 静的ファイル / MySQL

s1（入口）・s2（重いアプリ）・s3（DB）に役割を分ける。順番は s3 → env → memcached → s2 → s1 unix → nginx の順で崩さない。s1 unix と nginx は隣同士でやる（間にベンチを挟まない。unix 化直後は旧 nginx 設定のままなので 8080 が閉じて見える）。

流し方は全部同じ。**サーバに入って直接編集しない**。作業機の backup repo にファイルを作って push し、各台で pull して `cp` で移す。やり取りの枝は `feature/work-k-hoshihara` に統一する（`feature/split` には載せない）。作業機のブロックはすべて `~/srv-backup`（backup repo の手元 clone）で打つ。各反映の締めは restart + s1 からの公式ベンチ 1 本 + `scores.txt`。`fail` が 0 でなければ次に進まない。



### 1. 作業機 — IP を `backup/common/ips.sh` に書く

[1.](0020-split-1.md#1-起動したec2インスタンスを確認する) で控えたプライベート IP をファイルにする。シェル変数に入れるだけでは消えるので、heredoc で作る。以降の生成はこのファイルを `source` する。

**下の IP を自分の値に直してから**作業機（手元の private-isu-terraform）で実行し、push する

```bash

# localで作業する
git fetch origin
git switch feature/work-k-hoshihara 2>/dev/null || git switch -c feature/work-k-hoshihara
git pull --ff-only 2>/dev/null || true
mkdir -p backup/common/

cat > backup/common/ips.sh <<'EOF'
# s1 のプライベート IP（静的の rsync 用。後で使う）
WEB_PRIV='10.42.0.231'
# s2 のプライベート IP（重いアプリ、HTTP）
APP_PRIV='10.42.0.113'
# 共有 memcached。既定は s2 なので APP_PRIV と同じ
MC_PRIV='10.42.0.113'
# s3 のプライベート IP
DB_PRIV='10.42.0.182'
SOCK='/home/isucon/tmp/gunicorn.sock'
SITE='/etc/nginx/sites-enabled/isucon.conf'
EOF
cat backup/common/ips.sh
source backup/common/ips.sh

git add -A
git commit -m "split: 台の IP を backup/common/ips.sh に置く"
git push -u origin feature/work-k-hoshihara
```



### 2. MySQL（s3 だけ）

**目的:** s1・s2 から MySQL（s3）に届くようにする。作業機で設定ファイルを作る。

```bash
# private-isu-terraform で作業する
mkdir -p backup/s3/etc/mysql/mysql.conf.d backup/s3/home

# 旧名の 99-bind-all.cnf は消す。`mysqld.cnf` より辞書順で後になる名前にしないと
# `mysqld.cnf` 側の bind-address が後勝ちする（`99-` は先に読まれて負ける）
rm -rf ./backup/s3/etc/mysql/mysql.conf.d/zz-bind-all.cnf
cat > backup/s3/etc/mysql/mysql.conf.d/zz-bind-all.cnf <<'EOF'
[mysqld]
bind-address = 0.0.0.0
mysqlx-bind-address = 0.0.0.0
EOF

rm -rf ./backup/s3/home/grant-split.sql
cat > backup/s3/home/grant-split.sql <<'EOF'
CREATE USER IF NOT EXISTS 'isuconp'@'10.42.%' IDENTIFIED BY 'isuconp';
GRANT ALL PRIVILEGES ON isuconp.* TO 'isuconp'@'10.42.%';
FLUSH PRIVILEGES;
SELECT user, host FROM mysql.user WHERE user = 'isuconp';
EOF

git add -A && git commit -m "split: s3 の bind-all と GRANT" && git push
```

VPC CIDR が `10.42.0.0/16` 以外なら `grant-split.sql` の `10.42.%` を合わせる。現在の Terraform はこの CIDR なので原則変えなくてよい。

### 6. s1 の gunicorn（unix socket）

作業機で drop-in を作る:

```bash
git pull --ff-only
mkdir -p backup/s1/etc/systemd/system/isu-python.service.d

# ExecStart= の空行は元の -b 0.0.0.0:8080 を消すため
cat > backup/s1/etc/systemd/system/isu-python.service.d/unix.conf <<'EOF'
[Service]
WorkingDirectory=/home/isucon/private_isu/webapp/python
ExecStart=
ExecStart=/home/isucon/private_isu/webapp/python/.venv/bin/gunicorn \
  --bind unix:/home/isucon/tmp/gunicorn.sock \
  --umask 007 \
  app:app
EOF

git add -A && git commit -m "split: s1 の gunicorn を unix socket に" && git push
```



s1 で反映する:

```bash
REPO=/home/isucon/private-isu-terraform
cd "$REPO" && git fetch origin
git switch feature/work-k-hoshihara 2>/dev/null || git switch -c feature/work-k-hoshihara
git pull --ff-only
source "$REPO/backup/common/ips.sh"

# 1. 現行。ストックは -b 0.0.0.0:8080
systemctl cat isu-python.service

# 2. ソケットの置き場を用意する
mkdir -p /home/isucon/tmp
sudo chown isucon:www-data /home/isucon/tmp
sudo chmod 775 /home/isucon/tmp

# 3. daemon設定を編集
sudo cp -a "$REPO/backup/s1/etc/systemd/system/isu-python.service.d" /etc/systemd/system/
sudo systemctl daemon-reload

# 4. 再起動。sock が作られ、8080 は閉じる
sudo systemctl restart isu-python.service

# 5. 確認
# unix.conf が載っていること
systemctl cat isu-python.service

ls -l /home/isucon/tmp/gunicorn.sock

# ここで何も表示されないことを確認。 表示される場合、8080 portが開かれてしまっている
sudo ss -lntp | grep 8080

# unix socketへのファイル書き込みが発生していることを確認
sudo -u www-data curl --unix-socket /home/isucon/tmp/gunicorn.sock \
  -fsS -o /dev/null -m 5 http://localhost/login || \
  sudo journalctl -u isu-python.service -n 80 --no-pager
```

ついでに s1 の memcached を止める。§6 の restart で MC=s2 を載せ済みなので、§3 で一時的に起こした s1 の分はもう要らない:

```bash
# s1 で
sudo systemctl stop memcached.service

# 何も出ないこと（s1 の 11211 は閉じる。s2 のは §4 で 0.0.0.0 のまま）
sudo ss -lntp | grep 11211 || true
```



ソケットは `isucon:www-data`、モード `770` が目安（`--umask 007`）。nginx が 502 なら:

```bash
sudo usermod -aG isucon www-data
sudo systemctl reload nginx
```

unix 化直後はベンチを回さない。s1 の nginx が旧設定のままなので 8080 が閉じて見える。ベンチは §7 の nginx 反映の後に回す。

### 7. nginx（s1）— 静的 / 軽い unix / 重い HTTP

**目的:** ストックは全部 `proxy_pass http://localhost:8080;`。s1 の 8080 はもう無い。location で分ける。

**作るファイル:** `backup/s1/etc/nginx/conf.d/upstream.conf`（`upstream` 定義。http コンテキスト用）と `backup/s1/etc/nginx/sites-enabled/isucon.conf`（server 定義。ストックは短いので、**ファイル全体を置き換えてよい**）。

`upstream` は `server` ブロックの中に書けない（`nginx -t` が落ちる）。http 直下の別ファイルに分ける。

ローカルで実施

```bash
git pull --ff-only
source backup/common/ips.sh
mkdir -p backup/s1/etc/nginx/conf.d backup/s1/etc/nginx/sites-enabled

cat > backup/s1/etc/nginx/conf.d/upstream.conf <<EOF
upstream light {
  server unix:/home/isucon/tmp/gunicorn.sock;
}

upstream heavy {
  server ${APP_PRIV}:8080;
}
EOF

cat > backup/s1/etc/nginx/sites-enabled/isucon.conf <<EOF
server {
  listen 80;
  client_max_body_size 10m;
  root /home/isucon/private_isu/webapp/public/;

  location /css/ { }
  location /js/ { }
  location /img/ { }
  location = /favicon.ico { }

  location = /login {
    proxy_set_header Host \$host;
    proxy_pass http://light;
  }
  location = /logout {
    proxy_set_header Host \$host;
    proxy_pass http://light;
  }
  location = /register {
    proxy_set_header Host \$host;
    proxy_pass http://light;
  }

  location / {
    proxy_set_header Host \$host;
    proxy_pass http://heavy;
  }
}
EOF

git add -A && git commit -m "split: s1 の nginx を unix+重いHTTP に" && git push
```

### 静的ファイルと画像

`webapp/public/` に css / js / `img/`（UI）/ favicon。Flask は `static_folder=../public`。ストックの nginx は `root` がそのディレクトリだが、`location /` が全部 `proxy_pass` するので **静的もアプリ経由となってしまっている**。

投稿画像 `/image/<id>.<ext>` のストックは **MySQL `posts.imgdata`**。ディスク上のファイルではないので、ファイル化したら `/home/isucon/private_isu/webapp/public/image/` に置き（アプリの保存先変更は別途）、s1 の nginx で直接返すような構成にする。
ディスクに無い分はアプリ（MySQL）にフォールバックする。

#### 1. nginx に `/image/` を足す（作業機で EOF 編集→push→s1 で反映）

§7 の `isucon.conf` に `/image/` だけ足した全体を作る。`/image` をファイル化しないならこの節はやらない（重いアプリへ proxy のまま）。

- ローカルで下記のファイルを編集する

```sh

```

backup/s1/etc/nginx/sites-enabled/isucon.conf
```sh
server {
  listen 80;
  client_max_body_size 10m;
  root /home/isucon/private_isu/webapp/public/;

  location /css/ { }
  location /js/ { }
  location /img/ { }
  location = /favicon.ico { }

  location = /login {
    proxy_set_header Host $host;
    proxy_pass http://light;
  }
  location = /logout {
    proxy_set_header Host $host;
    proxy_pass http://light;
  }
  location = /register {
    proxy_set_header Host $host;
    proxy_pass http://light;
  }

  location /image/ {
    try_files $uri @app;
  }
  location @app {
    proxy_set_header Host $host;
    proxy_pass http://heavy;
  }

  location / {
    proxy_set_header Host $host;
    proxy_pass http://heavy;
  }
}
```

#### 2. ファイルの配置と削除（作業機の staging を正にする）

でかいバイナリを毎回 git に載せない。作業機の `staging/` を正とし、s1・s2 へは `rsync --delete` で配る。**サーバで直接 rm・編集しない**。消したいファイルは staging で消せば `--delete` で両台からも消える。

```bash
# 作業機
cd ~/srv-backup && git pull --ff-only
source backup/common/ips.sh
mkdir -p staging/public
# staging/ は commit しない（git add -A の巻き添え防止）
grep -qx 'staging/' .gitignore 2>/dev/null || echo 'staging/' >> .gitignore

# 初回だけ: s2 の現物を staging に持ってくる
rsync -a "isucon@${APP_PRIV}:/home/isucon/private_isu/webapp/public/" staging/public/

# 変更・削除は staging でやる
rm staging/public/js/old-bundle.js  # 例：消したいファイルはここで消す

# s1（nginx 配信用）・s2（アプリ参照用）に反映。消した分も --delete で消える
for h in "$WEB_PRIV" "$APP_PRIV"; do
  rsync -a --delete staging/public/ "isucon@${h}:/home/isucon/private_isu/webapp/public/"
done
```

```bash
# s1 で権限（nginx は `www-data`。`/home/isucon` が 750 だと 403）
sudo chmod o+x /home/isucon /home/isucon/private_isu /home/isucon/private_isu/webapp
sudo chmod -R a+rX /home/isucon/private_isu/webapp/public
# 所有者は isucon のままでよい
curl -fsS -o /dev/null -m 5 http://127.0.0.1/css/style.css
```

参照が残っているファイルを消すと 404 になる。テンプレート・アプリの参照も合わせて直すこと。SSH が通らない経路なら staging の tar を当日の手段（SSM 等）で運ぶ。

`/image` をファイルにするなら、アプリが書き込むディレクトリも同じ流し方で s1・s2 に配る（または共有しない構成なら nginx 台だけで完結させる）。**tmpfs や `/dev/shm` に置かない**（[0020-split-3 §10 の再起動試験](0020-split-3.md#10-ベンチ中の書き込みは再起動後も残す) で落ちる）。

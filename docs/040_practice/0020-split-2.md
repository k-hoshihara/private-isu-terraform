## 8. nginx / アプリ / 静的ファイル / MySQL

静的Assetファイルへの分割を実施する



### 1. 作業機 — IP を `backup/common/ips.sh` に書く

[1.](0020-split-1.md#1-起動したec2インスタンスを確認する) で控えたプライベート IP をファイルにする。シェル変数に入れるだけでは消えるので、heredoc で作る。以降の生成はこのファイルを `source` する。

**下の IP を自分の値に直してから**「ローカルのprivate-isu-terraform」で実行し、pushする

```bash
mkdir -p backup/common/

cat > backup/common/ips.sh <<'EOF'
# s1 のプライベート IP（静的の rsync 用。後で使う）
WEB_PRIV='10.42.0.90'
# s2 のプライベート IP（重いアプリ、HTTP）
APP_PRIV='10.42.0.171'
# 共有 memcached。既定は s2 なので APP_PRIV と同じ
MC_PRIV='10.42.0.171'
# s3 のプライベート IP
DB_PRIV='10.42.0.186'
SOCK='/home/isucon/tmp/gunicorn.sock'
SITE='/etc/nginx/sites-enabled/isucon.conf'
EOF
cat backup/common/ips.sh
source backup/common/ips.sh

git add -A
git commit -m "split: 台の IP を backup/common/ips.sh に置く"
git push -u origin feature/backup
```



### 2. MySQL（s3 だけ）

ローカル環境で作業を実施する。

まずはS1,S2サーバからMySQLにアクセスできるように設定する

```bash
# private-isu-terraform で作業する
git pull --ff-only
mkdir -p backup/s3/etc/mysql/mysql.conf.d backup/s3/home

cat > backup/s3/etc/mysql/mysql.conf.d/99-bind-all.cnf <<'EOF'
[mysqld]
bind-address = 0.0.0.0
mysqlx-bind-address = 0.0.0.0
EOF

cat > backup/s3/home/grant-split.sql <<'EOF'
CREATE USER IF NOT EXISTS 'isuconp'@'10.42.%' IDENTIFIED BY 'isuconp';
GRANT ALL PRIVILEGES ON isuconp.* TO 'isuconp'@'10.42.%';
FLUSH PRIVILEGES;
SELECT user, host FROM mysql.user WHERE user = 'isuconp';
EOF

git add -A && git commit -m "split: s3 の bind-all と GRANT" && git push
```

VPC CIDR が `10.42.0.0/16` 以外なら `grant-split.sql` の `10.42.%` を合わせる。現在の Terraform はこの CIDR なので原則変えなくてよい。



s3 で作業を実施：MySQLの設定を反映させる

```bash
REPO=/home/isucon/private-isu-terraform
cd "$REPO" && git fetch origin
git switch feature/backup 2>/dev/null || git switch -c feature/backup
git pull --ff-only

# 今 127.0.0.1:3306 であることを確認する。この状態では他サーバからアクセスができない
sudo ss -lntp | grep 3306

# 元ファイルを .orig として退避
sudo test -f /etc/mysql/mysql.conf.d/mysqld.cnf.orig || \
  sudo cp -a /etc/mysql/mysql.conf.d/mysqld.cnf /etc/mysql/mysql.conf.d/mysqld.cnf.orig

sudo cp -a "$REPO/backup/s3/etc/mysql/mysql.conf.d/99-bind-all.cnf" /etc/mysql/mysql.conf.d/
sudo mysql < "$REPO/backup/s3/home/grant-split.sql"

sudo systemctl restart mysql

# 0.0.0.0:3306 または *:3306 であることを確認する。 これで他サーバからアクセスができるようになる
sudo ss -lntp | grep 3306
```

### 3. アプリの env.sh（s1 と s2。同じ内容）

Python は初期設定なら DB=`localhost`、memcached=`127.0.0.1:11211`。これを **DB=s3、memcached=s2** に向ける。

ローカルの「private-isu-terraform」で作業を実施。

必要な設定ファイルを書き込みgitに反映する。

```bash
git pull --ff-only
source backup/common/ips.sh

cat backup/s1/home/env.sh

# s1, s2のenv.shにISUCONP_DB_HOST、ISUCONP_MEMCACHED_ADDRESSを追加する
for h in s1 s2; do
  grep -v '^ISUCONP_DB_HOST=\|^ISUCONP_MEMCACHED_ADDRESS=' backup/s1/home/env.sh > /tmp/env.new
  {
    echo "ISUCONP_DB_HOST=${DB_PRIV}"
    echo "ISUCONP_MEMCACHED_ADDRESS=${MC_PRIV}:11211"
  } >> /tmp/env.new
  cp /tmp/env.new backup/$h/home/env.sh
done

# env.shを確認する
cat backup/s1/home/env.sh
cat backup/s2/home/env.sh

git add -A && git commit -m "split: env.sh を DB=s3・memcached=s2 に向ける" && git push
```



s1 と s2 でenv.shを反映させ、s1, s2のDBをs3に向ける

```bash
REPO=/home/isucon/private-isu-terraform
cd "$REPO" && git fetch origin
git switch feature/backup 2>/dev/null || git switch -c feature/backup
git pull --ff-only

## s1の場合はこちら
sudo cp -a "$REPO/backup/s1/home/env.sh" /home/isucon/env.sh
## s2の場合はこちら
sudo cp -a "$REPO/backup/s2/home/env.sh" /home/isucon/env.sh

# cat をし、ISUCONP_DB_HOST が s3、ISUCONP_MEMCACHED_ADDRESS が s2のIP:11211 であることを確認
cat /home/isucon/env.sh
```

この時点では gunicorn はまだ古い環境のまま。`EnvironmentFile` は起動時に読むので、この状態ではBenchmarkは動かない。



### 4. s1 の gunicorn（unix socket）

ローカルのリポジトリで再度ファイルを編集

```bash
git pull --ff-only
mkdir -p backup/s1/etc/systemd/system/isu-python.service.d

# ExecStart= の空行は元の -b 0.0.0.0:8080 を消すため
cat > backup/s1/etc/systemd/system/isu-python.service.d/unix.conf <<'EOF'
[Service]
WorkingDirectory=/home/isucon/private_isu/webapp/python
ExecStart=
ExecStart=/home/isucon/private_isu/webapp/python/.venv/bin/gunicorn \
  --bind unix:/home/isucon/tmp/gunicorn.sock \
  --umask 007 \
  app:app
EOF

git add -A && git commit -m "split: s1 の gunicorn を unix socket に" && git push
```

s1 で反映する。この順:

```bash
REPO=/home/isucon/private-isu-terraform
cd "$REPO" && git fetch origin
git switch feature/split 2>/dev/null || git switch -c feature/split
git pull --ff-only
source "$REPO/backup/common/ips.sh"

# 1. 現行。ストックは -b 0.0.0.0:8080
systemctl cat isu-python.service

# 2. ソケットの置き場。所有者 isucon、グループ www-data、ディレクトリは 775
mkdir -p /home/isucon/tmp
sudo chown isucon:www-data /home/isucon/tmp
sudo chmod 775 /home/isucon/tmp

# 3. drop-in を移して読ませる
sudo cp -a "$REPO/backup/s1/etc/systemd/system/isu-python.service.d" /etc/systemd/system/
sudo systemctl daemon-reload

# 4. 再起動。sock が作られ、8080 は閉じる
sudo systemctl restart isu-python.service

# 5. 確認
systemctl cat isu-python.service    # unix.conf が載っていること
ls -l /home/isucon/tmp/gunicorn.sock
sudo ss -lntp | grep 8080 || echo '8080 closed (expected)'
sudo -u www-data curl --unix-socket /home/isucon/tmp/gunicorn.sock \
  -fsS -o /dev/null -m 5 http://localhost/login || \
  sudo journalctl -u isu-python.service -n 80 --no-pager
```

```bash
# 締めのベンチ（s1 で打つ）
mkdir -p ~/bench-notes
TS=$(date +%Y%m%d%H%M%S)
sudo mv /var/log/nginx/access.log /var/log/nginx/access.log.$TS
sudo nginx -s reopen
sudo -iu isucon /home/isucon/private_isu/benchmarker/bin/benchmarker \
  -u /home/isucon/private_isu/benchmarker/userdata \
  -t http://localhost
echo "$(date -Iseconds)  score=  pass=  fail=  note=split-s1unix" >> ~/bench-notes/scores.txt
```

ソケットは `isucon:www-data`、モード `770` が目安（`--umask 007`）。nginx が 502 なら:

```bash
sudo usermod -aG isucon www-data
sudo systemctl reload nginx
```





### 4. memcached（s2 だけ）

**目的:** ストックは `-l 127.0.0.1`。s1 の gunicorn から届かない。`-l 0.0.0.0` にする。

**作るファイル:** `backup/s2/etc/systemd/system/memcached.service.d/listen.conf`（drop-in で上書き。`/etc/memcached.conf` の sed はやらない）。

s2 で現行を確認する（読むだけ）:

```bash
systemctl cat memcached.service
sudo ss -lntp | grep 11211
```

作業機で作る。`ExecStart` のパスと `-u` と `-m` は上の `systemctl cat` に合わせ、`-l` だけ `0.0.0.0` にする。

```bash
cd ~/srv-backup && git pull --ff-only
mkdir -p backup/s2/etc/systemd/system/memcached.service.d

cat > backup/s2/etc/systemd/system/memcached.service.d/listen.conf <<'EOF'
[Service]
ExecStart=
ExecStart=/usr/bin/memcached -m 64 -p 11211 -u memcache -l 0.0.0.0
EOF

git add -A && git commit -m "split: memcached を 0.0.0.0 で listen" && git push
```

s2 で反映する:

```bash

echo stats | nc -w 1 127.0.0.1 11211 | head
```

### 7. nginx（s1）— 静的 / 軽い unix / 重い HTTP

**目的:** ストックは全部 `proxy_pass http://localhost:8080;`。s1 の 8080 はもう無い。location で分ける。

**作るファイル:** `backup/s1/etc/nginx/sites-enabled/isucon.conf`（`/etc/nginx/sites-enabled/isucon.conf` に置くもの。ストックは短いので、**ファイル全体を置き換えてよい**）。

作業機で作る。`APP_PRIV` は `backup/common/ips.sh` の値が入る。

```bash
cd ~/srv-backup && git pull --ff-only
source backup/common/ips.sh
mkdir -p backup/s1/etc/nginx/sites-enabled

cat > backup/s1/etc/nginx/sites-enabled/isucon.conf <<EOF
server {
  listen 80;
  client_max_body_size 10m;
  root /home/isucon/private_isu/webapp/public/;

  upstream light {
    server unix:/home/isucon/tmp/gunicorn.sock;
  }

  upstream heavy {
    server ${APP_PRIV}:8080;
  }

  location /css/ { }
  location /js/ { }
  location /img/ { }
  location = /favicon.ico { }

  location = /login {
    proxy_set_header Host \$host;
    proxy_pass http://light;
  }
  location = /logout {
    proxy_set_header Host \$host;
    proxy_pass http://light;
  }
  location = /register {
    proxy_set_header Host \$host;
    proxy_pass http://light;
  }

  location / {
    proxy_set_header Host \$host;
    proxy_pass http://heavy;
  }
}
EOF

git add -A && git commit -m "split: s1 の nginx を unix+重いHTTP に" && git push
```

heredoc をクォートしないので `${APP_PRIV}` が展開される。`tee` のときと同じく `$host` を nginx 変数のまま出すために `\$host` にしてある。手で書くなら `$host` でよい。

s1 で反映する:

```bash
REPO=/home/isucon/private-isu-terraform
cd "$REPO" && git fetch origin
git switch feature/split 2>/dev/null || git switch -c feature/split
git pull --ff-only
source "$REPO/backup/common/ips.sh"

ls -l /etc/nginx/sites-enabled
sudo cat "$SITE"
sudo test -f "${SITE}.orig" || sudo cp -a "$SITE" "${SITE}.orig"
sudo cp -a "$REPO/backup/s1/etc/nginx/sites-enabled/isucon.conf" "$SITE"
sudo nginx -t && sudo systemctl reload nginx
```

?&gt; 素体の `$SITE` は `sites-available/isucon.conf` への symlink。上の `cp` で通常ファイルに置き換わる。以後は `sites-available` 側ではなく `$SITE`（`sites-enabled` の実体）が正になる。戻すときは `${SITE}.orig` から戻す。

複数の重い app なら `upstream heavy` に `server` を並べる。`proxy_pass http://heavy;` のまま。

確認（s1）:

```bash

```

### 静的ファイルと画像

`webapp/public/` に css / js / `img/`（UI）/ favicon。Flask は `static_folder=../public`。ストックの nginx は `root` がそのディレクトリだが、`location /` が全部 `proxy_pass` するので **静的もアプリ経由**。

投稿画像 `/image/<id>.<ext>` のストックは **MySQL `posts.imgdata`**。ディスク上のファイルではない。nginx で `/css` `/js` `/img` `/image` を返すときは、ファイルを nginx 台へ置き、www-data が読めるようにする。

public を nginx 台へ（アプリ台から。SSH が通っているとき）:

```bash
# s2 で。s1 のプライベート IP は backup/common/ips.sh から
source /home/isucon/private-isu-terraform/backup/common/ips.sh
rsync -a --delete \
  /home/isucon/private_isu/webapp/public/ \
  "isucon@${WEB_PRIV}:/home/isucon/private_isu/webapp/public/"
```

SSM のみなら、作業機経由で tar を往復させる。

```bash
# 作業機。INSTANCE は terraform output の ID
SRC=i-app
DST=i-web
aws ssm start-session --target "$SRC"   # 中で tar czf /tmp/public.tgz -C /home/isucon/private_isu/webapp public
# 作業機へ取り出して DST へ置く、は当日の経路に合わせる
```

`/image` をファイルにしたら、上の `location /` より前に足す。未出力なら付けない（重いアプリへ proxy）。足すときも作業機の `backup/s1/etc/nginx/sites-enabled/isucon.conf` を編集して push し、s1 で pull → cp → reload の流し方で入れる。

```nginx
# location /image/ {
#   try_files $uri @app;
# }
# location @app {
#   proxy_set_header Host $host;
#   proxy_pass http://heavy;
# }
```

権限（nginx は `www-data`。`/home/isucon` が 750 だと 403）:

```bash
sudo chmod o+x /home/isucon /home/isucon/private_isu /home/isucon/private_isu/webapp
sudo chmod -R a+rX /home/isucon/private_isu/webapp/public
# 画像ディレクトリを足したら同様。所有者は isucon のままでよい
```

`/image` をファイルにするなら、アプリが書き込むディレクトリを nginx 台へ rsync する（または共有しない構成なら nginx 台だけで完結させる）。**tmpfs や `/dev/shm` に置かない**（[後半 §10 の再起動試験](0020-split-3.md#10-ベンチ中の書き込みは再起動後も残す) で落ちる）。

# 0110 複数台に分割する

[0100-overall-tuning.md](0100-overall-tuning.md) までを、**1 台に全部ある状態**で終えたら、3 台に分けて役割を割ります。

- この章は、台の確認・バックアップ・役割決め・分割前ベースラインまでです。
- 役割は、s1（nginx + 軽いアプリ）/ s2（重いアプリ + 共有 memcached）/ s3（MySQL）です。

- 3 台がまだなら、[0010-env.md](0010-env.md) §4 の `webapp_instance_count = 3` で増やします（ここまで作業した台を s1 にします）。
- 増やした台は、AMI 直後の状態です。`backup/base`（基準線。変更しない元の状態）は入れておきます。
- 計測ツール（`nc` を含む）は、[0010-setup.md](../010_common/0010-setup.md) の「計測ツール」で入れてあります。
- 出口は、[0110-split-2.md](0110-split-2.md) → [0110-split-3.md](0110-split-3.md) → [0110-split-4.md](0110-split-4.md) です。

?> 分けると、点数は一時的に下がります（台をまたぐ通信と、画像データの転送が入るため）。下がった理由を特定して戻し、1 台に全部入った構成を超えるのが [0110-split-4.md](0110-split-4.md) です。

## 1. 起動した EC2 インスタンスを確認します

IP はマネジメントコンソール（GUI）で確認します。

- ローカルから、SSM（AWS が用意する接続機能）で接続します。

```bash

# isuconユーザへ切り替え

# ISUCON prompt。台ごとに 1 行だけ実行する（ISUCON1 / ISUCON2 / ISUCON3）

source env.sh
```



- サイト設定（nginx の設定ファイル）の実体は、AMI では `isucon.conf` です。
- 無ければ、`ls /etc/nginx/sites-enabled` から確認します。

EC2 への接続は、EC2 > 接続から開ける Session Manager（GUI）を使います。



- s1 に入って、動作確認のベンチを 1 本回します。

```bash
# s1 で実行する。Session Manager で入った直後なら、先に sudo su - isucon だけを単独で実行する
```

- 通れば OK です。
- 失敗したら先に進まず、[0110-split-3.md §11](0110-split-3.md#11-ヘルスチェックと公式ベンチ) で切り分けます。

**実行したら、スコアを手元に控えておきます**



### 実行前準備：GitHub へアクセスできる状況にする

#### 認証（各台で 1 回）

- AMI に `gh`（GitHub の操作ツール）は入っていません。入れます。
- 手元のブラウザにコードを入れるだけで、通ります。

```bash
sudo apt-get update -y && sudo DEBIAN_FRONTEND=noninteractive apt-get install -y gh
gh --version

# GitHub.com → HTTPS → Y（git の認証にも使う）→ Login with a web browser
gh auth login
```

- 3 つ目の「Authenticate Git with your GitHub credentials?」は、**Y** にします。
- `gh` が git の認証の取次（credential helper）になります。

```bash
gh auth status

# !gh auth git-credential と出れば Y が効いている
git config --get credential.https://github.com.helper
```

- **SSM の `send-command` で実行する場合は、`gh auth setup-git` が別途必要です。**
- `gh auth login --web` は、対話の入力待ちを飛ばします。3 つ目に Y を答えられず、認証の取次が設定されません。
- `gh auth status` は、認証の取次に依存しません。**通ってしまいます。**
- ただし、`git push` は落ちます。

```text
fatal: could not read Username for 'https://github.com': No such device or address
```

- 対話シェル（Session Manager の GUI）なら、上の手順だけで足ります。
- 対話なしで実行する場合（非対話実行）は、`setup-git` を足してください。

- `--skip-ssh-key` のような新しいオプションは、AMI の `gh`（Ubuntu 版 2.45 前後）で `unknown flag` になります。
- 使わないでください。

#### 非対話実行の例（`send-command` 経由）

- `gh auth login --web` は端末の入力を読むため、そのままでは止まります。
- 別の場所で起動して（バックグラウンド起動）、表示されたコードを回収します。

```bash
cd /home/isucon
nohup sudo -u isucon -H gh auth login --hostname github.com --git-protocol https --web \
  >/tmp/ghlogin.log 2>&1 </dev/null &
sleep 8
cat /tmp/ghlogin.log
# ! First copy your one-time code: XXXX-XXXX
# Open this URL to continue in your web browser: https://github.com/login/device
```

- コードを入力して認証した後、`gh auth setup-git` で認証の取次を設定します。

```bash
sudo -u isucon -H gh auth setup-git
git config --get credential.https://github.com.helper
# !/usr/bin/gh auth git-credential
```

- **`sudo -u isucon -H` を付けるのは、必須です。**
- `send-command` は root で実行されます。
- `HOME` が空のまま `gh` を走らせると、`/home/isucon/.config/gh` が `root:root 0700` で作られます。`isucon` から読めなくなります。

```text
failed to read configuration: open /home/isucon/.config/gh/config.yml: permission denied
```

- そうなったら、`backup/` を積む前に直します。

```bash
sudo chown -R isucon:isucon /home/isucon/.config/gh
```

## 3. 分割前のバックアップ

- サーバ操作（次の Python 切替（[§4](#4-python-に切り替える全台)）を含む）を始める前に、取ります。
- これ以降で、`/etc`・`env.sh`・gunicorn の受け付け設定（bind）を変えます。

### 各台で `~/kit-backup`（Linux 設定）

- s1 / s2 / s3 の **全部** で行います。
- `isucon` で打ちます。

```bash
TS=$(date +%Y%m%d%H%M%S)
BK=/home/isucon/kit-backup/target
mkdir -p "$BK/etc" "$BK/home"

# /etc は allowlist だけ拾う。全量 cp しない（shadow やホスト鍵を抱えない）
for p in nginx mysql memcached.conf sysctl.d systemd/system security/limits.conf; do
  if sudo test -e "/etc/$p"; then
    dest="$BK/etc/$(dirname "$p")"
    mkdir -p "$dest"
    sudo cp -a "/etc/$p" "$dest/"
  fi
done

# unit の実体の置き場所を控えておく（後の drop-in でパスを合わせるため）
systemctl cat isu-python.service > "$BK/isu-python.service.txt" 2>/dev/null || true

# home は env.sh とアプリのソースだけ。$HOME 丸ごとはやらない
cp -a /home/isucon/env.sh "$BK/home/"
rsync -a --exclude '.venv/' --exclude '.git/' --exclude 'node_modules/' \
  --exclude 'benchmarker/' \
  /home/isucon/private_isu/ "$BK/home/private_isu/"

# sudo cp で作ったので root 所有。isucon から読めるようにする
sudo chown -R isucon:isucon "$BK"

find "$BK" -maxdepth 2 -ls
# file sizeの確認
du -sh "$BK"
```



#### リポジトリに取り込む（各台）

- `HOST` を `backup/s1` → `backup/s2` → `backup/s3` と変えて、3 台分入れます。

- 退避先は 3 台とも `~/kit-backup/target` です。`TS` はコミットメッセージに書く時刻です
- s2・s3 も s1 と同じ手順で初期投入します

```bash
# 台ごとに s1 / s2 / s3
cd $HOME
HOST='backup/s1'
# HOST='backup/s2'
# HOST='backup/s3'
```

- 以下で clone して、`backup/s1`〜`backup/s3` に配置します。

```bash
REPO=/home/isucon/private-isu-terraform

# env.sh に DB 認証情報が入る。public リポジトリにしない
[ -d "$REPO/.git" ] || gh repo clone k-hoshihara/private-isu-terraform "$REPO"

# sudo cp で作ったので root 所有。isucon から読めるようにする（コピー手順で済みなら不要）
sudo chown -R isucon:isucon "$BK"

D="$REPO/$HOST"
mkdir -p "$D/home"

# /etc は $BK の時点で allowlist 済み（shadow / ssh host key / sudoers なし）。丸ごと移す
cp -a "$BK/etc" "$D/etc"

# アプリと env.sh。.venv と .git は除く
# benchmarker/ は $BK に入れていない（~/kit-backup/common/ にある）。AMI の配布物で自分では書き換えないのでリポジトリにも入れない
# --delete だけでは除外したファイルは受信側に残る。除外を足して打ち直すときは --delete-excluded が要る
rsync -a --delete --delete-excluded \
  --exclude '.venv/' --exclude '.git/' --exclude 'node_modules/' \
  "$BK/home/private_isu/" "$D/home/private_isu/"
cp -a "$BK/home/env.sh" "$D/home/env.sh"

du -sh "$D"

# 重いものが紛れていないか push の前に見る。GitHub は 50MB 超で警告、100MB 超は push を拒否する
find "$D" -type f -size +50M -printf '%s %p\n' | sort -rn | head
du -sh "$D"/home/private_isu/* | sort -h | tail -10
```

- バックアップするのは、**自分が書き換えるもの**（アプリのソース、`/etc` の設定、`env.sh`）だけです。
- ビルドで作られる成果物は、入れません。
- ベンチマーカーの設定を変えたときだけ、そのファイルを個別に足します。



#### push

- やり取りは、feature ブランチ（作業用の枝）でやります。main には直接 push しません。
- 初回バックアップの枝は、`feature/backup` です。s1 が作り、s2・s3 は同じ枝に入ります。
- 順番にやります。

```bash
cd "$REPO"
git config user.name  "<GitHub ユーザー名>"
git config user.email "<GitHub に登録したメールアドレス>"

# 自分専用のBranchを作成し、そこにpushする
git switch -c feature/backup

# 重いファイルや __pycache__ が巻き込まれないことを push 前に確認する
git status --short | head -20

git add -A
git commit -m "$HOST: 分割前ベースライン ($TS)"

# 2 台目以降。他の台が先に push している。初回は枝が無いので落ちたら飛ばす
git pull --rebase origin feature/backup
git push -u origin feature/backup
```

3 台分、同じ `feature/backup` に積みます。

- AMI 側で clone したリポジトリの remote（送り先）は、**`origin` だけ**です（`gh repo clone` が作るため）。
- 作業機に `fork` のような別の remote があっても、AMI 側では `origin` に push します。
- `git push fork feature/backup` とすると、`fatal: 'fork' does not appear to be a git repository` になります。

- **`git add -A` の前に、`backend.hcl` が追跡対象外になっているか確認します。**
- AMI 側は Terraform を使っていないので、`backend.hcl` は存在しません。
- 念のため、`.git/info/exclude` に入れておくと安全です。
- S3 バケット名 = アカウント ID を含みます。commit すると公開されます。

```bash
grep -qx 'backend.hcl' .git/info/exclude || echo 'backend.hcl' >> .git/info/exclude
printf '%s\n' '__pycache__/' '*.pyc' '*.orig' >> .git/info/exclude
git add -A --dry-run | head -10
```

- `__pycache__/` や `*.orig` は、`app.py` を編集したときにできます。
- `git add -A` は、それらを巻き込みます。除外してから commit します。

## 5. 役割を考える

- 基本は、s1 が入口、s2 が重いアプリ、s3 が DB です。


| 役割           | 起動状態にする                                                                 | 停止状態にする                                         |
| ------------ | ----------------------------------------------------------------------- | ----------------------------------------------- |
| s1 `web,app` | nginx。`public/` の静的。gunicorn は **unix socket**（同じ台の中の内部接続。軽い処理）。memcached は s2 を使う | MySQL。ローカル memcached。HTTP の 8080 は開けない（unix だけ） |
| s2 `app`     | gunicorn **:8080**（重い処理）。共有 memcached（Flask-Session）                    | nginx、MySQL、Ruby                                |
| s3 `db`      | MySQL                                                                   | nginx、gunicorn、Ruby、memcached                   |


- `/css` `/js` `/img` `/favicon.ico` → ディスク（s1）
- 軽いアプリ（ログインなど）→ s1 の unix socket
- 残り（`/`、`/posts`、`/image`、投稿）→ s2 の `http://APP_PRIV:8080`

- ログイン状態（セッション）を各台のメモリで持ちたくないため、共有 memcached を 1 本だけ起動させます。
- 置き場は、重い処理を回す s2 です（実測で s1 が良ければ変えます）。

## 7. 余ったプロセスを止める

- `disable --now` にします。
- `stop` だけだと、再起動で戻ります（[python.md](../010_common/webapp-setup/python.md)）。

- **アプリの記憶（セッションなど）の共有は、memcached を使います。**
- 実体は、s2 の 1 本だけです。
- s1 の軽い gunicorn も、s2 を見ます。

```bash
systemctl list-unit-files --type=service --no-legend | grep -Ei 'isu|python|ruby|go|nginx|mysql|memcached'

# 見やすく表示
printf '%-24s %-10s %-10s\n' UNIT ACTIVE ENABLED
for u in nginx.service mysql.service mysqld.service isu-python.service isu-ruby.service isu-go.service isu-node.service memcached.service; do
  systemctl list-unit-files --type=service --no-legend | awk '{print $1}' | grep -qx "$u" || continue
  printf '%-24s %-10s %-10s\n' "$u" "$(systemctl is-active "$u")" "$(systemctl is-enabled "$u")"
done
```

- **全台**で、次を実行します（§4 の Python 切替で済みなら飛ばします）。

```bash
sudo systemctl disable --now isu-ruby.service
sudo systemctl disable --now isu-go.service 2>/dev/null || true
sudo systemctl disable --now isu-node.service 2>/dev/null || true
```



- **s1（web + 軽いアプリ）**
- ローカル memcached は、止めます（2 本目を立てません）。
- gunicorn は、次節で s2 の 11211 を見ます。

# 配布・状態・終盤

アプリの rsync や my.cnf 一括投入はスクリプトにしない。当日の値に直して打つ。

## アプリを 1 台へ配る

```bash
HOST=s1
USER=isucon
SRC=./webapp                   # サーバ上で直接直すなら rsync は不要
DEST=/home/isucon/webapp
UNIT=isu-python.service
PORT=8080

ssh "$USER@$HOST" "mkdir -p ~/kit-backup && tar czf ~/kit-backup/app.prev.tgz -C '$DEST' ."
rsync -a --delete \
  --exclude '.venv/' --exclude '__pycache__/' --exclude '.git/' \
  "$SRC/" "$USER@$HOST:$DEST/"
ssh "$USER@$HOST" "cd '$DEST/python' && (command -v uv >/dev/null && uv sync || true)"
ssh "$USER@$HOST" "sudo systemctl restart '$UNIT' && systemctl is-active '$UNIT'"
ssh "$USER@$HOST" "curl -fsS -o /dev/null -m 5 http://127.0.0.1:${PORT}/"
```

サーバ上で直接編集しているなら再起動だけ。

```bash
sudo systemctl restart isu-python.service
systemctl is-active isu-python.service
curl -fsS -o /dev/null -m 5 http://127.0.0.1:8080/
journalctl -u isu-python.service -n 40 --no-pager
```

戻す:

```bash
ssh isucon@s1 "tar xzf ~/kit-backup/app.prev.tgz -C /home/isucon/webapp && sudo systemctl restart isu-python.service"
```

複数台はホストを変えて同じブロックを打つ。

```bash
for HOST in s1 s2; do
  echo "===== $HOST ====="
  ssh "isucon@$HOST" "sudo systemctl restart isu-python.service && systemctl is-active isu-python.service"
done
```

## nginx / MySQL の設定

テンプレは `etc/nginx/ltsv.conf` と `etc/mysql/mysqld-isucon.cnf`。  
**my.cnf は 1 項目ずつコメントを外してから配る。** `innodb_buffer_pool_size` をまとめて入れない。

```bash
HOST=s1
ssh isucon@$HOST "sudo cp -a /etc/nginx /home/isucon/kit-backup/nginx.prev || true"
scp etc/nginx/ltsv.conf isucon@$HOST:/tmp/ltsv.conf
ssh isucon@$HOST "sudo mv /tmp/ltsv.conf /etc/nginx/conf.d/00-ltsv.conf && sudo nginx -t && sudo systemctl reload nginx"

ssh isucon@$HOST "sudo cp -a /etc/mysql /home/isucon/kit-backup/mysql.prev || true"
scp etc/mysql/mysqld-isucon.cnf isucon@$HOST:/tmp/99-isucon.cnf
ssh isucon@$HOST "sudo mv /tmp/99-isucon.cnf /etc/mysql/mysql.conf.d/99-isucon.cnf && sudo systemctl restart mysql"
```

## サービス状態

```bash
UNIT=isu-python.service
printf '%-28s %-10s %-10s\n' UNIT ACTIVE ENABLED
for u in nginx.service mysql.service mysqld.service "$UNIT"; do
  systemctl list-unit-files --type=service --no-legend | awk '{print $1}' | grep -qx "$u" || continue
  printf '%-28s %-10s %-10s\n' "$u" "$(systemctl is-active "$u")" "$(systemctl is-enabled "$u")"
done
systemctl list-unit-files --type=service --no-legend | awk '{print $1}' | grep -Ei 'isu|python|golang'
```

再起動後に Go/Ruby が enabled に戻っていないかを見る。

## ディスク

`long_query_time=0` のスローログで埋まりやすい。

```bash
df -h /
sudo du -xh /var/log /home /tmp 2>/dev/null | sort -h | tail -n 20
sudo truncate -s 0 /var/log/nginx/access.log /var/log/mysql/mysql-slow.log
sudo journalctl --vacuum-time=1d
```

## ログを止める（終盤）

計測オフだけでスコアが伸びることがある。止めたことを確認する。

```bash
SITE=/etc/nginx/sites-enabled/isucon
sudo test -f "${SITE}.logs-off.bak" || sudo cp -a "$SITE" "${SITE}.logs-off.bak"
sudo sed -i 's#^[[:space:]]*access_log[^;]*;#    access_log off;#' "$SITE"
sudo nginx -t && sudo systemctl reload nginx
mysql -e 'SET GLOBAL slow_query_log=0;'
sudo pkill -f 'py-spy record' || true

grep access_log "$SITE"
mysql -N -e 'SELECT @@slow_query_log'
pgrep -af 'py-spy record' || echo 'py-spy stopped'
```

戻す:

```bash
sudo cp -a /etc/nginx/sites-enabled/isucon.logs-off.bak /etc/nginx/sites-enabled/isucon
sudo nginx -t && sudo systemctl reload nginx
mysql -e 'SET GLOBAL slow_query_log=1;'
```

## 再起動試験

1. 上の「サービス状態」を取る  
2. `sudo reboot`（複数台なら 1 台ずつ）  
3. 起動を待つ  
4. サービス状態をもう一度  
5. `curl -fsS -o /dev/null -m 5 http://127.0.0.1:8080/`  
6. 公式ベンチ 1 本  

自分を reboot したセッションは切れる。入り直してから 4 以降。

## 終盤チェック（17:00 以降）

- [ ] 再起動後もベンチが通るか  
- [ ] 全サービスが active かつ enabled か（Go/Ruby が戻っていないか）  
- [ ] 貼ったインデックスが残っているか（`SHOW INDEX`。[00300-measure.md](00300-measure.md#インデックス)）  
- [ ] access_log / slow / py-spy が止まっているか  
- [ ] ディスクに空きがあるか  
- [ ] フロント（トップ・ログイン・投稿）が壊れていないか  
- [ ] `innodb_buffer_pool_size` を入れたなら、入れる前後のスコアを比べたか  
- [ ] ベンチマーカーの向き先が意図した app 台か  

## ログを追う

```bash
sudo tail -F /var/log/nginx/access.log
sudo tail -F /var/log/mysql/mysql-slow.log
sudo journalctl -f -u isu-python.service
```

## 備考

### 配布後に 502 / ヘルスチェック失敗

```bash
UNIT=isu-python.service
systemctl is-active "$UNIT"
sudo journalctl -u "$UNIT" -n 80 --no-pager
curl -v http://127.0.0.1:8080/
```

退避があれば戻す。`~/kit-backup/app.prev.tgz`。

### nginx -t が失敗する

```bash
sudo nginx -t
sudo cp -a /home/isucon/kit-backup/nginx.prev /etc/nginx   # 取ってあれば
# またはサイト設定の .orig
sudo nginx -t && sudo systemctl reload nginx
```

### mysqld が起きない（99-isucon.cnf の直後）

```bash
sudo journalctl -u mysql -n 80 --no-pager
sudo rm -f /etc/mysql/mysql.conf.d/99-isucon.cnf
sudo rm -f /etc/mysql/mysql.conf.d/99-isucon-slow.cnf
sudo systemctl restart mysql
```

`innodb_buffer_pool_size` は 1 項目ずつ。

### ディスクが埋まった

```bash
df -h /
sudo du -xh /var/log /home /tmp 2>/dev/null | sort -h | tail
```

主犯はスローログが多い。truncate するか、終盤ならログを止める。

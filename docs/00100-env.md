# 練習環境の構築（手順書）

このリポジトリの Terraform で、private-isu 用 EC2 を AWS 上に立てる手順です。  

本番までの方針:

1. 手順は Markdown のコードブロックのまま残す
2. ラッパーの `.sh` は書かない（何をしているか追えなくなる）
3. 当日、実機を見てから、この手順を種に Ansible を書く

競技サーバに入ったあとの作業は [00200-setup.md](00200-setup.md)。

## 前提

作業は AWS CloudShell 上。ローカルにツールを入れる必要はない。

| 項目 | 内容 |
| --- | --- |
| AWS アカウント | EC2・VPC・IAM・S3（state 用）を操作できる権限 |
| 作業環境 | AWS CloudShell（AWS CLI v2 と Git 入り） |
| Terraform | >= 1.10（S3 backend の `use_lockfile`） |
| リージョン | `ap-northeast-1` |
| state | S3。CloudShell のホームが消えても `destroy` できる |

> [!WARNING]
> `c7a.large` は起動中ずっと課金される。中断するときは停止、不要なら `terraform destroy`。

特に断りのない `terraform` は `terraform/` で実行する。

## 1. Terraform を入れる（CloudShell 初回のみ）

ホームは永続化されるので、次回のセッションでは不要。

```bash
git clone --depth=1 https://github.com/tfutils/tfenv.git ~/.tfenv
mkdir -p ~/bin
ln -sf ~/.tfenv/bin/* ~/bin/
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
echo 'export TF_DATA_DIR=/tmp/.terraform' >> ~/.bashrc
source ~/.bashrc

tfenv install latest
tfenv use latest
terraform -version
echo "$TF_DATA_DIR"   # /tmp/.terraform であること
```

`TF_DATA_DIR` はプロバイダバイナリの置き場。Linux 版 AWS プロバイダは約 850MB あり、CloudShell の永続領域（1GB）を食い潰す。`/tmp` なら消えてもよい。

`/tmp` はセッション切れで空になる。開き直したら `terraform init` をやり直す。state は S3 にある。

## 2. リポジトリを取る

```bash
cd ~
git clone https://github.com/k-hoshihara/private-isu-terraform.git
cd private-isu-terraform
```

## 3. state 用 S3 バケット（初回のみ）

本編の EC2 とは別に、CLI で先に作る。`tfvars` では指定できない。

| 接頭辞 | バケット名 |
| --- | --- |
| なし | `private-isu-tfstate-<アカウントID>` |
| `myname` | `myname-private-isu-tfstate-<アカウントID>` |

接頭辞は英小文字・数字・ハイフン。同じアカウントを複数人で使うときだけ付ける。

```bash
REGION=ap-northeast-1
PREFIX=                         # 付けるなら myname。無しなら空
ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
if [ -n "$PREFIX" ]; then
  BUCKET="${PREFIX}-private-isu-tfstate-${ACCOUNT_ID}"
else
  BUCKET="private-isu-tfstate-${ACCOUNT_ID}"
fi
echo "bucket=$BUCKET"

if aws s3api head-bucket --bucket "$BUCKET" 2>/dev/null; then
  echo "already exists"
else
  aws s3api list-buckets \
    --query "Buckets[?contains(Name, 'private-isu-tfstate')].Name" --output table

  aws s3api create-bucket --bucket "$BUCKET" --region "$REGION" \
    --create-bucket-configuration "LocationConstraint=${REGION}"
  aws s3api put-bucket-versioning --bucket "$BUCKET" \
    --versioning-configuration Status=Enabled
  aws s3api put-public-access-block --bucket "$BUCKET" \
    --public-access-block-configuration \
    BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
  aws s3api put-bucket-encryption --bucket "$BUCKET" \
    --server-side-encryption-configuration \
    '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"},"BucketKeyEnabled":true}]}'
fi

cd ~/private-isu-terraform/terraform
cat > backend.hcl <<EOF
bucket = "${BUCKET}"
EOF
```

`backend.hcl` は git に入れない。既存バケットへ繋ぐだけなら、作成を飛ばして名前だけ書けばよい。  
本編を `destroy` してもバケットは残る。不要ならコンソールまたは `aws s3 rb`（中の state も消える）。

接頭辞を変えると別バケットになる。後から `destroy` するときも初回と同じ名前にする。

忘れたとき:

```bash
aws s3api list-buckets \
  --query "Buckets[?contains(Name, 'private-isu-tfstate')].Name" \
  --output table
```

## 4. terraform.tfvars

```bash
cd ~/private-isu-terraform/terraform
cp terraform.tfvars.example terraform.tfvars
```

`allowed_cidrs` は自分のグローバル IP。ブラウザで https://checkip.amazonaws.com を開く。  
CloudShell で `curl` すると CloudShell の IP になる。

```bash
MY_IP=203.0.113.1   # ブラウザで確認した値
sed -i "s|203\.0\.113\.1/32|${MY_IP}/32|" terraform.tfvars
cat terraform.tfvars
```

`vi terraform.tfvars` でもよい。このファイルは git に入れない。

## 5. 構築

```bash
cd ~/private-isu-terraform/terraform
source ~/.bashrc
echo "$TF_DATA_DIR"

terraform init -backend-config=backend.hcl
terraform plan
terraform apply
```

`no space left on device` なら `TF_DATA_DIR` が空のまま走っている。

```bash
rm -rf .terraform
source ~/.bashrc
echo "$TF_DATA_DIR"
terraform init -backend-config=backend.hcl
```

以前ローカル state だった場合の初回だけ:

```bash
terraform init -backend-config=backend.hcl -migrate-state
```

`webapp_url` をブラウザで開き、Iscogram が出れば完了。

## 8. ベンチ（3 章）

同じホストから `localhost` へ。

```bash
sudo su - isucon
/home/isucon/private_isu/benchmarker/bin/benchmarker \
  -u /home/isucon/private_isu/benchmarker/userdata \
  -t http://localhost
```

ベンチがホスト CPU を食い始めたら `terraform.tfvars` で分離して `apply`。

```hcl
enable_benchmarker_instance = true
benchmarker_instance_type   = "c7a.xlarge"
```

## 9. 停止・削除

```bash
# 中断（EBS 課金は残る）
aws ec2 stop-instances --instance-ids $(terraform output -raw webapp_instance_id)

# 再開
aws ec2 start-instances --instance-ids $(terraform output -raw webapp_instance_id)
terraform apply -refresh-only
terraform output webapp_url   # パブリック IP は変わる
```

不要になったら:

```bash
terraform destroy
```

AMI にセキュリティ更新は入らない。長期間つけっぱなしにしない。

### ホームが消えたとき

```bash
source ~/.bashrc
echo "$TF_DATA_DIR"
cd ~
git clone https://github.com/k-hoshihara/private-isu-terraform.git
cd private-isu-terraform

REGION=ap-northeast-1
PREFIX=                         # 初回と同じ
ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
if [ -n "$PREFIX" ]; then
  BUCKET="${PREFIX}-private-isu-tfstate-${ACCOUNT_ID}"
else
  BUCKET="private-isu-tfstate-${ACCOUNT_ID}"
fi
cd terraform
printf 'bucket = "%s"\n' "$BUCKET" > backend.hcl
cp terraform.tfvars.example terraform.tfvars
# allowed_cidrs を書く。destroy だけなら任意の /32 でよい

terraform init -backend-config=backend.hcl
terraform destroy
```

| 期間 | 対応 |
| --- | --- |
| 数日〜数週間 | インスタンス停止。EBS のみ課金 |
| しばらく使わない | `terraform destroy` |

state バケットは `destroy` では消えない。

## Terraform 変数

| 変数 | デフォルト | 説明 |
| --- | --- | --- |
| `region` | `ap-northeast-1` | AMI の公開リージョン |
| `allowed_cidrs` | （必須） | HTTP/SSH の接続元。`0.0.0.0/0` は不可 |
| `ami_id` | `ami-09201e964bee13733` | 競技者用 AMI |
| `webapp_instance_type` | `c7a.large` | 競技者用 |
| `enable_benchmarker_instance` | `false` | 3 章は `false` |
| `benchmarker_instance_type` | `c7a.xlarge` | ベンチ分離時 |
| `root_volume_size` | `40` | GiB |
| `enable_ssh` | `false` | SSM だけなら `false` |
| `key_name` | `null` | SSH するときだけ |
| `install_alp` | `true` | **練習用**。起動時に alp を入れる user_data。本番では使わない |
| `alp_version` | `1.0.21` | そのときの alp |
| `vpc_cidr` | `10.42.0.0/16` | |
| `subnet_cidr` | `10.42.0.0/24` | |

## 備考

### `echo "$TF_DATA_DIR"` が空 / no space left on device

`~/.bashrc` に書いていないか、`source` していない。書きかけの `.terraform` を消してからやり直す。

```bash
rm -rf terraform/.terraform
source ~/.bashrc
echo "$TF_DATA_DIR"
cd terraform && terraform init -backend-config=backend.hcl
```

### `head-bucket` や `create-bucket` が失敗する

権限、リージョン、バケット名の衝突を見る。同じアカウントに別名の `*-private-isu-tfstate-*` が無いか `list-buckets` する。接頭辞を変えると別バケットになり、古い state は見えない。

### `TargetNotConnected`

インスタンス起動直後。1〜2 分待って SSM をやり直す。

```bash
aws ssm start-session --target $(terraform output -raw webapp_instance_id)
```

### `webapp_url` が古い

停止して起動するとパブリック IP が変わる。

```bash
terraform apply -refresh-only
terraform output webapp_url
```

### 課金が止まらない

`terraform destroy` しても state バケットは残る。EC2 が残っていないかはコンソールか `aws ec2 describe-instances` で見る。

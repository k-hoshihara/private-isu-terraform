# 0010 AMI から 2 台を立てる

ISUCon 14 の公式 AMI から、アプリ用 1 台とベンチ用 1 台を AWS CLI で立てる手順です。立てたら [0020-https.md](0020-https.md) へ進みます。

この AMI は ISUCon 14 の競技と同じ構成です。

| 項目 | 値 |
| --- | --- |
| AMI | `ami-0e334c50145a3ee41`（リージョン `ap-northeast-1`、Ubuntu 24.04） |
| 競技者のインスタンス | `c5.large`（2 vCPU / 4 GiB）+ gp3 20 GB × 3 |
| ベンチマーカー | ECS Fargate 8 vCPU |
| 最初の SSH ユーザー | `ubuntu` ユーザー（`isucon` ではありません） |

?> 公式 README に「AMI は予告なく利用できなくなる可能性があります」とあります。`describe-images` が `InvalidAMIID.NotFound` を返したら、この手順では立てられません。[代替の AMI ビルド](#ami-が-使えないとき) を参照してください。

## 1. AMI を確認します

地域が東京になっていることを確認してから見ます。`ap-northeast-1` 以外で AMI を引くと `InvalidAMIID.NotFound` になります。

```bash
aws ec2 describe-images \
  --region ap-northeast-1 \
  --image-ids ami-0e334c50145a3ee41 \
  --query 'Images[0].[ImageId,State,Name,PublicIpv4PoolSupport]' \
  --output table
```

`State` が `available` なら使えます。`deregistered` や `InvalidAMIID.NotFound` なら AMI が公開から消えています。

## 2. 作業ディレクトリを作ります

このフォルダの手順で使う変数と記録は、ここにまとめます。手順 4 から 9 までは同じシェルで続けて実行してください（作った変数を次の手順で使います）。

```bash
mkdir -p ~/isucon14
cd ~/isucon14
```

## 3. SSH 鍵を用意します

既存の鍵があれば飛ばします。新しく作るときは、鍵名だけ入れます（`aws` が秘密鍵の本体を出力します）。

```bash
KEY_NAME=isucon14
if ! aws ec2 describe-key-pairs --key-names "$KEY_NAME" >/dev/null 2>&1; then
  aws ec2 create-key-pair --key-name "$KEY_NAME" \
    --query KeyMaterial --output text > ~/.ssh/${KEY_NAME}.pem
  chmod 600 ~/.ssh/${KEY_NAME}.pem
fi
ssh-keygen -y -f ~/.ssh/${KEY_NAME}.pem
```

成功の見え方: 最後の行に `ssh-ed25519 AAAA...` のような公開鍵が 1 行出ます。

## 4. VPC とサブネットを作ります

可用ゾーンは東京リージョンの 1 つ目を使います。

```bash
REGION=ap-northeast-1
AZ=$(aws ec2 describe-availability-zones --region $REGION \
  --query 'AvailabilityZones[0].ZoneName' --output text)
echo "AZ=$AZ"

VPC_ID=$(aws ec2 create-vpc --cidr-block 10.0.0.0/16 --query Vpc.VpcId --output text)
aws ec2 modify-vpc-attribute --vpc-id "$VPC_ID" --enable-dns-hostnames
SUBNET_ID=$(aws ec2 create-subnet --vpc-id "$VPC_ID" --cidr-block 10.0.1.0/24 \
  --availability-zone "$AZ" --query Subnet.SubnetId --output text)
IGW_ID=$(aws ec2 create-internet-gateway --query InternetGateway.InternetGatewayId --output text)
aws ec2 attach-internet-gateway --vpc-id "$VPC_ID" --internet-gateway-id "$IGW_ID"
RTB_ID=$(aws ec2 create-route-table --vpc-id "$VPC_ID" --query RouteTable.RouteTableId --output text)
aws ec2 create-route --route-table-id "$RTB_ID" --destination-cidr-block 0.0.0.0/0 \
  --gateway-id "$IGW_ID"
aws ec2 associate-route-table --route-table-id "$RTB_ID" --subnet-id "$SUBNET_ID"
```

成功の見え方: 4 つの `vpc-` `subnet-` `igw-` `rtb-` で始まる ID が変数に入ります。`echo "$VPC_ID $SUBNET_ID"` で空でないことを確認します。

## 5. セキュリティグループを作ります

2 台とも同じグループに入れます。22 は自分のグローバル IP からだけにします。ブラウザで [https://checkip.amazonaws.com](https://checkip.amazonaws.com) を開いて値を得ます。

```bash
MY_IP='203.0.113.1'   # 自分のグローバル IP に書き換える
SG_ID=$(aws ec2 create-security-group --group-name isucon14-sg \
  --description 'ISUCon14 practice' --vpc-id "$VPC_ID" \
  --query GroupId --output text)
aws ec2 authorize-security-group-ingress --group-id "$SG_ID" \
  --protocol tcp --port 22 --cidr "${MY_IP}/32"
aws ec2 authorize-security-group-ingress --group-id "$SG_ID" \
  --protocol tcp --port 443 --cidr 0.0.0.0/0
aws ec2 describe-security-groups --group-ids "$SG_ID" \
  --query 'SecurityGroups[0].IpPermissions[].{Port:FromPort,Cidr:IpRanges[].CidrIp}' \
  --output table
```

443 は全世界に開けておきます。ベンチ用インスタンスから HTTPS でアクセスするためです。22 は自分からのみだけにします。
成功の見え方: テーブルに `22`（自分の IP だけ）と `443`（`0.0.0.0/0`）の 2 行が出ます。

## 6. アプリ用インスタンスを立てます

```bash
AMI_ID=ami-0e334c50145a3ee41
APP_ID=$(aws ec2 run-instances \
  --image-id "$AMI_ID" \
  --instance-type c5.large \
  --key-name "$KEY_NAME" \
  --security-group-ids "$SG_ID" \
  --subnet-id "$SUBNET_ID" \
  --associate-public-ip-address \
  --block-device-mappings 'DeviceName=/dev/sda1,Ebs={VolumeSize=20,VolumeType=gp3,DeleteOnTermination=true,Encrypted=true}' \
  --metadata-options HttpTokens=required \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=isucon14-app},{Key=Project,Value=isucon14}]' \
  --query 'Instances[0].InstanceId' --output text)
echo "APP_ID=$APP_ID"
```

成功の見え方: `i-` で始まる ID が出ます。

## 7. ベンチ用インスタンスを立てます

ベンチは対象サーバとは別の台にします。同じ台で回すと、計測対象の CPU をベンチが奪い合うためです。

```bash
BENCH_ID=$(aws ec2 run-instances \
  --image-id "$AMI_ID" \
  --instance-type c5.xlarge \
  --key-name "$KEY_NAME" \
  --security-group-ids "$SG_ID" \
  --subnet-id "$SUBNET_ID" \
  --associate-public-ip-address \
  --block-device-mappings 'DeviceName=/dev/sda1,Ebs={VolumeSize=30,VolumeType=gp3,DeleteOnTermination=true,Encrypted=true}' \
  --metadata-options HttpTokens=required \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=isucon14-bench},{Key=Project,Value=isucon14}]' \
  --query 'Instances[0].InstanceId' --output text)
echo "BENCH_ID=$BENCH_ID"
```

成功の見え方: `i-` で始まる ID が出ます。

## 8. 2 台が `running` になるまで待ちます

OS の起動に 1〜2 分かかります。`running` になっても SSH が拒否されることがあります。少し待って試します。

```bash
aws ec2 wait instance-running --instance-ids "$APP_ID" "$BENCH_ID"
aws ec2 describe-instances --instance-ids "$APP_ID" "$BENCH_ID" \
  --query 'Reservations[0].Instances[].{Id:InstanceId,Name:Tags[?Key==`Name`].Value | [0],State:State.Name,IP:PublicIpAddress}' \
  --output table
```

## 9. IP アドレスを控えます

このあとの手順は IP を手で打たない形にしました。`env.sh` に書いて読み込みます。

```bash
cd ~/isucon14
cat > env.sh <<'EOF'
export AWS_REGION=ap-northeast-1
export KEY_NAME=isucon14
export VPC_ID="__VPC_ID__"
export SUBNET_ID="__SUBNET_ID__"
export SG_ID="__SG_ID__"
export AMI_ID=ami-0e334c50145a3ee41
export APP_ID="__APP_ID__"
export BENCH_ID="__BENCH_ID__"
EOF
sed -i "s|__VPC_ID__|$VPC_ID|; s|__SUBNET_ID__|$SUBNET_ID|; s|__SG_ID__|$SG_ID|; s|__APP_ID__|$APP_ID|; s|__BENCH_ID__|$BENCH_ID|" env.sh

aws ec2 describe-instances --instance-ids "$APP_ID" "$BENCH_ID" \
  --query 'Reservations[0].Instances[].[InstanceId,PublicIpAddress]' --output text \
  | while read -r id ip; do
      printf 'export %s_IP=%s\n' "$([ "$id" = "$APP_ID" ] && echo APP || echo BENCH)" "$ip" >> env.sh
    done
source env.sh
cat env.sh
grep -q 'APP_IP=.' env.sh || { echo 'IP が取れていません。手順 8. をやり直します'; exit 1; }
```

成功の見え方: `APP_IP=...` と `BENCH_IP=...` の 2 行が出ています。

## 10. アプリ用サーバにログインします

AMI の SSH ユーザーは `ubuntu` です。`isucon` で直接ログインはしません。

```bash
source ~/isucon14/env.sh
ssh -i ~/.ssh/${KEY_NAME}.pem ubuntu@${APP_IP}
```

入ったらアプリを実行するユーザーへ切り替えます。

```bash
sudo su - isucon
whoami        # isucon
cat /home/isucon/env.sh
```

`env.sh` の中身は次のとおりです。これが唯一の接続設定です。

```text
ISUCON_DB_HOST="127.0.0.1"
ISUCON_DB_PORT="3306"
ISUCON_DB_USER="isucon"
ISUCON_DB_PASSWORD="isucon"
ISUCON_DB_NAME="isuride"

# マッチング間隔（秒）
ISUCON_MATCHING_INTERVAL=0.5
```

## 11. 起動直後の中身を確認します

```bash
sudo systemctl list-units 'isuride*' --no-pager
sudo nginx -t
grep isuride /etc/hosts
```

成功の見え方:

- `isuride-go.service` と `isuride-matcher.service` と `isuride-payment_mock.service` が `active`。`isuride-python.service` は `inactive`（0030 で使います）
- `nginx -t` が `syntax is ok` と `test is successful`
- `/etc/hosts` に `127.0.0.1 isuride.xiv.isucon.net` がある（マッチング処理がこれを通して自分自身を呼ぶため）

アプリが立っていることは、`0020` で HTTPS を通したあとに確認します。この時点では AMI 同梱の証明書が失効しているので `-k` を付けます。

## 12. AMI が使えないとき

公式 AMI が公開から消えた場合は、公式リポジトリの Packer で作り直します（公式 README の「自分でAMIをビルドする場合」）。`make all` はフロントエンドとベンチマーカーのビルド、Ansible の投入、Packer の AMI 作成までを 1 通りで走らせます。Packer・Ansible・Node.js・Go が必要です。

```bash
git clone --depth 1 https://github.com/isucon/isucon14.git ~/isucon14-src
cd ~/isucon14-src/provisioning/packer
make all
aws ec2 describe-images --region ap-northeast-1 \
  --owners self --filters 'Name=name,Values=isucon14_contestant-*' \
  --query 'sort_by(Images,&CreationDate)[-1].[ImageId,Name,CreationDate]' --output table
```

成功の見え方: `isucon14_contestant-<commit>-<日付>` という名前の AMI が 1 行出ます。`1. AMI を確認します` に戻り、`AMI_ID` をこの値に置き換えて最初からやり直します。

## 13. 停止と削除

練習が続くあいだは台を残します。中断はインスタンスの停止で足ります（EBS だけ課金されます）。

```bash
source ~/isucon14/env.sh
# 中断
aws ec2 stop-instances --instance-ids "$APP_ID" "$BENCH_ID"
# 再開（パブリック IP は変わります）
aws ec2 start-instances --instance-ids "$APP_ID" "$BENCH_ID"
```

不要になったら、タグが付いているリソースから消します。

```bash
source ~/isucon14/env.sh
aws ec2 describe-instances --filters \
  "Name=tag:Project,Values=isucon14" \
  "Name=instance-state-name,Values=pending,running,stopping,stopped" \
  --query 'Reservations[0].Instances[].InstanceId' --output text \
  | xargs -r aws ec2 terminate-instances --instance-ids
aws ec2 delete-security-group --group-id "$SG_ID"
aws ec2 delete-subnet --subnet-id "$SUBNET_ID"
aws ec2 delete-route-table --route-table-id "$RTB_ID"
aws ec2 detach-internet-gateway --vpc-id "$VPC_ID" --internet-gateway-id "$IGW_ID"
aws ec2 delete-internet-gateway --internet-gateway-id "$IGW_ID"
aws ec2 delete-vpc --vpc-id "$VPC_ID"
```

AMI にはセキュリティ更新が入りません。長いあいだ起動したままにしません。

| 期間 | 対応 |
| --- | --- |
| 数日〜数週間 | インスタンス停止（EBS のみ課金） |
| しばらく使わない | 上記の削除手順 |

?> AMI の EBS は `DeleteOnTermination=true` なので、インスタンスを消せばボリュームも消えます。

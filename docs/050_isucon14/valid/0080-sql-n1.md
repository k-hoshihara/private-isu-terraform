# 0080 N+1 を潰す

[0070-sql-columns.md](0070-sql-columns.md) で `chairs` に**最新の座標**（`last_latitude` / `last_longitude`）を持たせました。この章は、それを使って**ループの中のクエリ**を消します。

AMI の実装は、こうなっています。

```python
# app_handlers.py の app_get_nearby_chairs（AMI のまま）
chairs = conn.execute(text("SELECT * FROM chairs")).fetchall()   # 全椅子
for chair in chairs:
    if not chair.is_active:
        continue
    rows = conn.execute(                                      # 椅子ごとに 1 回
        text("SELECT * FROM rides WHERE chair_id = :chair_id ORDER BY created_at DESC"),
        {"chair_id": chair.id},
    ).fetchall()
    for ride in rides:
        status = get_latest_ride_status(conn, ride.id)         # ライドごとに 1 回
        ...
    row = conn.execute(                                        # 椅子ごとに 1 回
        text("SELECT * FROM chair_locations WHERE chair_id = :chair_id ORDER BY created_at DESC LIMIT 1"),
        {"chair_id": chair.id},
    ).fetchone()
```

**椅子の数 × ライドの数**だけクエリが増えます。3 台構成で測ったときは、これが `nearby-chairs` の 1 回 **1,059 ms** の正体でした。

## 1. 「今ライド中の椅子」を 1 クエリで集めます

AMI には「ライド中の椅子」をまとめて引く手がありませんでした。**1 クエリで集めます。**

```python
        busy_chair_ids = set(
            conn.execute(
                text(
                    """
                    SELECT DISTINCT rides.chair_id
                    FROM rides
                    WHERE rides.chair_id IS NOT NULL
                      AND rides.evaluation IS NULL
                    """
                )
            ).scalars()
        )
```

?> **`evaluation IS NULL` で同じ意味になります。**このアプリでは `COMPLETED` は**評価の送信（`POST /api/app/rides/{ride_id}/evaluation`）のときだけ**、`rides.evaluation` を書くのと**同じトランザクションで**入ります。だから「最新の状態が `COMPLETED` でない」＝「`evaluation` がまだ無い」です。**状態を数えるのをやめて、1 つの列を見るだけ**にしました。

?> 先に 3 台構成で、**古い書き方（`ride_statuses` 全体を `GROUP BY` + `GROUP_CONCAT`）と結果の集合が完全に一致すること**（`old_only=0` / `new_only=0`）を確かめてあります。ついでに、間に合わせで試した**相関サブクエリ版は 1.8 倍遅かった**（10.9 ms → 20.0 ms）ので戻しました。**測ってから入れます。**

## 2. 座標は `chairs` から引きます

```python
        rows = conn.execute(
            text(
                """
                SELECT id, name, model,
                       last_latitude AS latitude, last_longitude AS longitude
                FROM chairs
                WHERE is_active = TRUE
                  AND last_latitude IS NOT NULL
                ORDER BY id
                """
            )
        ).fetchall()
```

?> `last_latitude IS NOT NULL` は、元の `INNER JOIN` と同じ意味です（一度も座標を送っていない椅子は出てきません）。

## 3. `get_chair_stats` も 1 クエリにします

`app_get_notification` は、椅子が決まったライドで `get_chair_stats` を呼びます。AMI の実装は「椅子のライドを取って、**1 台ずつ `ride_statuses` を引く**」形でした。

```python
# app/app_handlers.py の get_chair_stats を差し替え
def get_chair_stats(conn, chair_id):
    row = conn.execute(
        text(
            """
            SELECT COUNT(*) AS total_ride_count,
                   IFNULL(AVG(rides.evaluation), 0) AS total_evaluation_avg
            FROM rides
            WHERE rides.chair_id = :chair_id
              AND rides.evaluation IS NOT NULL
              AND (SELECT COUNT(*)
                   FROM ride_statuses
                   WHERE ride_statuses.ride_id = rides.id
                     AND ride_statuses.status IN ('ARRIVED', 'CARRYING', 'COMPLETED')) = 3
            """
        ),
        {"chair_id": chair_id},
    ).fetchone()
    return AppGetNotificationResponseChairStats(
        total_rides_count=int(row.total_ride_count),
        total_evaluation_avg=float(row.total_evaluation_avg),
    )
```

`ARRIVED` / `CARRYING` / `COMPLETED` の 3 つがそろっているライドだけを数えます（元のループと同じ判定です）。

## 4. 実測（単一インスタンス、2026-10-18）

| 手 | 実測スコア（`pass=true` のみ） |

| `nearby-chairs` の N+1 + `evaluation IS NULL` | **1244 / 1637** |
| `get_chair_stats` を 1 クエリに | **1505 / 1811** |

`performance_schema` の実行回数が減っているかを確かめます。

- `SELECT * FROM chair_locations WHERE chair_id = ? ... LIMIT 1`（椅子ごとの最新座標）: **消えました**
- `SELECT * FROM ride_statuses WHERE ride_id = ? ORDER BY created_at`（`get_chair_stats` のライドごと）: **消えました**
- 代わりに `SELECT DISTINCT rides.chair_id FROM rides WHERE rides.chair_id IS NOT NULL AND rides.evaluation IS NULL`（326 回 / 29.5 秒）が残ります

?> `種別エラー数` が **`map[]`** になりました。`nearby-chairs` の N+1 と `get_chair_stats` が遅いあいだは `map[25:...]`（オーナーの椅子一覧のタイムアウト）や `map[26:...]`（データの不一致）が混じっていました。**遅さがエラーを生んでいた**わけです。

## 2. 効いた順（3 つ）

1. **マッチング**（0110）: `ORDER BY RAND()` をやめて**近い空き椅子を 1 クエリ**で選ぶ。**約 2.6 倍**。スコアの式（乗車位置との距離 × 0.1・完了数 × 5）に直接効く
2. **3 台分割 + DB 専用**（0160 / 0170）: 単一 7403 → 分割 14694 → **DB 専用 21819**。**同じ SQL が 45〜118 分の 1** になった
3. **通知の往復と `COMMIT`**（0090 / 0120）: `UNION ALL` で 1 往復、`connect()` + 書き込み時だけ `commit()`。`COMMIT` 35,565 → 6,996 回

## 4. 最終構成

| 台 | 役割 | 主な設定 |
| --- | --- | --- |
| `app-1` | nginx + アプリ | `keepalive 64`（上流）、`workers = 4`、`accesslog = None` |
| `app-2` | アプリ | `workers = 4`、`accesslog = None` |
| `app-3` | **MySQL 専用** | `max_connections = 1000`、`innodb_flush_log_at_trx_commit = 2`、`sync_binlog = 0`、`bind-address = 0.0.0.0` |

**SQL は 11 本の索引**（0060 の 10 + 0180 の 1）と **5 つの列**（`chairs.total_distance` / `last_latitude` / `last_longitude` / `completed_count` / `evaluation_sum`）。

**最終 digest**（DB 専用・窓の合計）: `COMMIT` 0.51 ms、通知の `UNION ALL` 0.39 ms、`rides WHERE chair_id` 0.19 ms。**`slp` は 0 件**。

## 5. 判断のルール（この教材で使ったもの）

1. **1 手 = ベンチ 2〜3 本。いちばん悪い回で比べる。**単一インスタンスでは **±40%** ぶれたので、1 本では決められません
2. **スコアが動かない手は、digest / alp で決める。**`COMMIT` の回数、`rows_examined`、実行回数（例: 窓関数が 39 回のまま増えない）
3. **窓をまたいで比べるときは、リクエスト数で正規化する。**アプリが速くなると、ベンチは**そのぶん多くリクエストを出す**（50,043 → 152,662）
4. **`slp` が空なら、もう SQL は遅くない。**次に見るのは `alp`（どのエンドポイントか）と CPU（`user` / `sys` / `iowait`）
5. **`iowait` が小さく `user+sys` が大きいなら、CPU の取り合い。**索引を足す前に、**DB に専用の CPU を渡す**

## 6. 後片付け

**この教材では `terraform destroy` を実行しません**（環境は残します）。止めるときは、**先にアプリとベンチを止めてから**です。

```bash
# 各台で（順番はどれでもよい）
sudo systemctl stop isuride-python isuride-matcher isuride-payment_mock nginx mysql
```

?> **`backup/isucon14/` の `s1` / `s2` / `s3` が最終状態**です（`s1` = app-1、`s2` = app-2、`s3` = app-3）。`restore.sh <名前>` で**同じ構成に戻せます**。`base` は AMI のままで、**公式リポジトリと一致**することを確かめてあります（[0015](0015-backup.md)）。

## 7. 残っている手（測っていないもの）

| 案 | 根拠 | 注意 |
| --- | --- | --- |
| app-3 に **worker 2 つだけ**アプリを置く | app-3 は DB 専用で CPU に余裕。alp の AVG 0.12 s は順番待ち | DB の CPU を食うと 0170 の逆戻り。**必ず 2 本測る** |
| `chair/coordinate` の `chair_locations` 読み直しを消す | 通知の `INSERT` のあと、同じ行を読み直している | `recorded_at` の値が変わる。**ベンチの検証に触る** |
| アプリの 1 リクエストあたりのクエリを 5 → 3 に | `users FOR SHARE`（0190 で削除済み）の残り | 削る前に alp で**どのエンドポイントか**を確かめる |
| `pymysql` → C ドライバ | CPU が上限なので効くはず | この AMI の Python 3.13 ではビルドできない |

?> **スコアが 2 万台で頭打ちに見えるときは、まず CPU を見てください。**この環境では **app-1 / app-2 の 4 コア**が上限で、`alp` の AVG 0.12 s は**待ち時間**です。**DB は 1 ms で返しています。**

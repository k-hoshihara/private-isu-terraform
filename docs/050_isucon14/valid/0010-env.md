# 0010 練習環境を作る（Terraform）

このリポジトリの Terraform で、ISURIDE 用の EC2 を AWS 上に立てます。アプリ用 1 台と、ベンチマーカー用 1 台の 2 台です。立てたら [0020-https.md](0020-https.md) へ進みます。

- 0010〜0100 は、アプリ 1 台に全部入った構成で進めます。
- **0160-split.md**（この章はこれから） で、競技と同じ 3 台に分けます。

立てるもの:

| 役割 | 台数 | スペック | ボリューム |
| --- | --- | --- | --- |
| アプリ | 1 台（`app_instance_count = 1`） | `c5.large`（2 vCPU / 4 GiB） | gp3 20 GB |
| ベンチマーカー | 1 台 | `c5.xlarge`（4 vCPU） | gp3 30 GB |

- AMI は ISUCon 14 の Ubuntu 24.04（リージョン `ap-northeast-1`）。
- 2 台は同じセキュリティグループに入れ、**互いに全ポートで届く**ようにします。ベンチ → アプリの HTTPS と、アプリ → ベンチの決済モックを通すためです。

?> `c5.large` と `c5.xlarge` は、起動中ずっと課金されます。中断するときは停止し、不要なら `terraform destroy` します。

`terraform` コマンドは、`docs/050_isucon14/terraform/` で実行します。

## 1. Terraform を入れる（初回のみ）

- CloudShell（ブラウザ上で動く AWS のターミナル）から用意するなら 1-a。
- 手元のパソコンから用意するなら 1-b。
- どちらも、2 回目以降は不要です。

<a id="1-a-cloudshell-を使う"></a>

### 1-a. CloudShell を使う

- CloudShell のホームは、消えずに残ります。
- 2 回目以降は、1-a を飛ばします。

```bash
cd /tmp
git clone --depth=1 https://github.com/tfutils/tfenv.git ~/.tfenv
mkdir -p ~/bin
ln -sf ~/.tfenv/bin/* ~/bin/
echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
echo 'export TF_DATA_DIR=/tmp/.terraform' >> ~/.bashrc
source ~/.bashrc

tfenv install latest
tfenv use latest
terraform -version
echo "$TF_DATA_DIR"   # /tmp/.terraform であること
```

- `TF_DATA_DIR` は、Terraform の部品（プロバイダ）を置く場所の指定です。
- CloudShell の保存領域は 1 GB しかありません。使い切らないように、`/tmp` にします。
- `/tmp` は、セッションが切れると空になります。開き直したら `terraform init` をやり直します。
- 作成記録（state）は S3 に置くので、`/tmp` が消えても残ります。

<a id="1-b-ローカルから-aws-login-でデプロイする"></a>

### 1-b. ローカルから `aws login` でデプロイする

- `aws login` は、AWS CLI v2 でないと使えません。
- Terraform は 1.10 以上にします。

```bash
# AWS CLI v2 でなければ、先に v2 を入れる
aws --version

aws login
aws sts get-caller-identity --query Account --output text

mise install terraform@latest
mise use -g terraform@latest
terraform -version
```

## 2. リポジトリを取る（初回のみ）

```bash
cd /tmp
git clone https://github.com/k-hoshihara/private-isu-terraform.git
# ブランチを変えたい場合はこちら
# BRANCH_NAME='develop/XXX'
# git clone -b ${BRANCH_NAME} https://github.com/k-hoshihara/private-isu-terraform.git

cd private-isu-terraform/docs/050_isucon14/terraform
```

## 3. SSH 鍵を用意する（初回のみ）

- 既存の鍵があれば飛ばします。
- 新しく作るときは、鍵名だけ入れます（`aws` が秘密鍵の本体を出力します）。

```bash
KEY_NAME=isucon14
if ! aws ec2 describe-key-pairs --key-names "$KEY_NAME" >/dev/null 2>&1; then
  aws ec2 create-key-pair --key-name "$KEY_NAME" \
    --query KeyMaterial --output text > ~/.ssh/${KEY_NAME}.pem
  chmod 600 ~/.ssh/${KEY_NAME}.pem
fi
ssh-keygen -y -f ~/.ssh/${KEY_NAME}.pem
```

成功の見え方: 最後の行に `ssh-ed25519 AAAA...` のような公開鍵が 1 行出ます。

## 4. state 用 S3 バケット（初回のみ）

- 本編の EC2 とは別に、コマンドで先に作ります。
- `tfvars`（設定ファイル）では指定できません。
- 親の [`../../terraform/`](../../../terraform) と同じバケットを使います。`key` で分けるので、衝突しません。

| 接頭辞 | バケット名 |
| --- | --- |
| なし | `private-isu-tfstate-<アカウントID>` |
| `myname` | `myname-private-isu-tfstate-<アカウントID>` |

- 接頭辞は、英小文字・数字・ハイフンで書きます。
- 同じアカウントを複数人で使うときだけ、付けます。

```bash
# 接頭辞。無しなら空でよい
PREFIX=''

## ここから下はコピペでOK
REGION=ap-northeast-1
ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
if [ -n "$PREFIX" ]; then
  BUCKET="${PREFIX}-private-isu-tfstate-${ACCOUNT_ID}"
else
  BUCKET="private-isu-tfstate-${ACCOUNT_ID}"
fi
echo "bucket=$BUCKET"

if aws s3api head-bucket --bucket "$BUCKET" 2>/dev/null; then
  echo "already exists"
else
  aws s3api list-buckets \
    --query "Buckets[?contains(Name, 'private-isu-tfstate')].Name" --output table

  aws s3api create-bucket --bucket "$BUCKET" --region "$REGION" \
    --create-bucket-configuration "LocationConstraint=${REGION}"
  aws s3api put-bucket-versioning --bucket "$BUCKET" \
    --versioning-configuration Status=Enabled
  aws s3api put-public-access-block --bucket "$BUCKET" \
    --public-access-block-configuration \
    BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
  aws s3api put-bucket-encryption --bucket "$BUCKET" \
    --server-side-encryption-configuration \
    '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"},"BucketKeyEnabled":true}]}'
fi

cd /tmp/private-isu-terraform/docs/050_isucon14/terraform
cat > backend.hcl <<EOF
bucket = "${BUCKET}"
EOF
```

- `backend.hcl` は、git に入れません。
- 既に存在するバケットに繋ぐだけなら、作成を飛ばして名前を書けば十分です。
- 本編を `destroy` しても、バケットは残ります。
- 不要なら、コンソールか `aws s3 rb` で消します（中の state も消えます）。

## 5. terraform.tfvars

```bash
cd /tmp/private-isu-terraform/docs/050_isucon14/terraform
cp terraform.tfvars.example terraform.tfvars
```

- `allowed_cidrs` には、自分のグローバル IP を書きます。
- ブラウザで [https://checkip.amazonaws.com](https://checkip.amazonaws.com) を開いて、確認します。
- CloudShell で `curl` すると、CloudShell の IP になります（確認はブラウザで行います）。

```bash
# ブラウザで確認した値
MY_IP='203.0.113.1'

# コピペでOK
sed -i "s|203\.0\.113\.1/32|${MY_IP}/32|" terraform.tfvars
cat terraform.tfvars
```

- `vi terraform.tfvars` でも編集できます。
- このファイルは、git に入れません。

### 台数

- ここだけが、1 台と複数台の違いです。
- example の既定は `3` です。
- 0010〜0100 は 1 台で進めます。`1` にします。
- **0160-split.md**（この章はこれから） で分けるときに `3` にします。

```hcl
# 0010〜0100（この章）
app_instance_count = 1

# 0110 の分割（example の既定）
# app_instance_count = 3
```

- あとから `3` に書き換えて apply すると、2 台増えます。
- `key_name` は `isucon14` のままでよいです。`3.` で作った鍵と一致します。

?> 公式 AMI `ami-0e334c50145a3ee41` は公開停止済みです（`describe-images` が `Images: []` を返します）。そのため、既定の `ami_id` を公開中の ISUCon 14 AMI `ami-0fcf9e8e8675a9ee4` に差し替えてあります。触らなくてかまいません。

## 6. 構築

```bash
cd /tmp/private-isu-terraform/docs/050_isucon14/terraform

# TF_DATA_DIR は CloudShell 経路（1-a）だけが設定します。
# ローカル（1-b）から進めた場合、空のままでも init は通ります（既定の .terraform/ を使う）。
source ~/.bashrc 2>/dev/null || true
echo "TF_DATA_DIR=${TF_DATA_DIR:-(未設定 → 既定の .terraform/ を使う)}"

terraform init -backend-config=backend.hcl
terraform plan
terraform apply
```

- apply 直後は、まだアプリが立ち上がっていません。
- AMI 内部の初期化（nginx / MySQL / アプリ）に、1〜2 分かかります。
- `terraform output` が出たら、1〜2 分待ってから次の手順へ進みます。

## 7. SSH でログインする

- アプリの IP と、ベンチの IP を控えます。
- `terraform output -raw env_sh` をそのまま `~/isucon14/env.sh` にします。

```bash
mkdir -p ~/isucon14
cd /tmp/private-isu-terraform/docs/050_isucon14/terraform
terraform output -raw env_sh > ~/isucon14/env.sh
source ~/isucon14/env.sh
cat ~/isucon14/env.sh
```

成功の見え方: `export APP_IP=...` / `export BENCH_IP=...` / `export BENCH_PRIV=...` に行ができています。`APP_IP` はアプリ機のパブリック IP、`BENCH_IP` はベンチ機のパブリック IP、`BENCH_PRIV` はベンチ機のプライベート IP です（`--payment-url` は `BENCH_PRIV` を使います。[0040-bench.md](0040-bench.md) の手順 3）。

- SSH のユーザーは `ubuntu` です（`isucon` ではありません）。

```bash
ssh -i ~/.ssh/${KEY_NAME}.pem ubuntu@${APP_IP}
```

- 入ったら、アプリを実行するユーザーへ切り替えます。

```bash
sudo su - isucon
whoami        # isucon
cat /home/isucon/env.sh
```

`env.sh` の中身は次のとおりです。これが唯一の接続設定です。

```text
ISUCON_DB_HOST="127.0.0.1"
ISUCON_DB_PORT="3306"
ISUCON_DB_USER="isucon"
ISUCON_DB_PASSWORD="isucon"
ISUCON_DB_NAME="isuride"

# マッチング間隔（秒）
ISUCON_MATCHING_INTERVAL=0.5
```

```bash
sudo systemctl list-units 'isuride*' --no-pager
sudo nginx -t
grep isuride /etc/hosts
```

成功の見え方:

- `isuride-go.service` と `isuride-matcher.service` と `isuride-payment_mock.service` が `active`。`isuride-python.service` は `inactive`（[0030-python.md](0030-python.md) で使います）
- `nginx -t` が `syntax is ok` と `test is successful`
- `/etc/hosts` に `127.0.0.1 isuride.xiv.isucon.net` がある（マッチング処理がこれを通して自分自身を呼ぶため）

?> この時点では AMI 同梱の TLS 証明書がベンチの信頼ストアに入っていません（自己署名です）。HTTPS の確認は [0020-https.md](0020-https.md) で証明書を差し替えてから行います。

<a id="ami-が-使えないとき"></a>

## 9. AMI が使えないとき

- 既定の AMI も公開停止になった場合は、公式リポジトリの Packer で作り直します（公式 README の「自分でAMIをビルドする場合」）。
- `make all` は、フロントエンドとベンチマーカーのビルド、Ansible の投入、Packer の AMI 作成までを 1 通りで走らせます。
- 手元に Packer・Ansible・Node.js・Go が必要です。

```bash
git clone --depth 1 https://github.com/isucon/isucon14.git ~/isucon14-src
cd ~/isucon14-src/provisioning/packer
make all
aws ec2 describe-images --region ap-northeast-1 \
  --owners self --filters 'Name=name,Values=isucon14_contestant-*' \
  --query 'sort_by(Images,&CreationDate)[-1].[ImageId,Name,CreationDate]' --output table
```

成功の見え方: `isucon14_contestant-<commit>-<日付>` という名前の AMI が 1 行出ます。`terraform.tfvars` の `ami_id` をこの値に書き換えて、`6.` からやり直します。

## 10. 停止と削除

- 練習が続くあいだは台を残します。中断はインスタンスの停止で足ります（EBS だけ課金されます）。
- 再開するとパブリック IP が変わります。`env.sh` を作り直します。

```bash
cd /tmp/private-isu-terraform/docs/050_isucon14/terraform

# 中断（EBS のみ課金）
aws ec2 stop-instances \
  --instance-ids $(terraform output -json app_instance_ids | jq -r '.[]') $(terraform output -raw benchmarker_instance_id)

# 再開
aws ec2 start-instances \
  --instance-ids $(terraform output -json app_instance_ids | jq -r '.[]') $(terraform output -raw benchmarker_instance_id)

terraform apply -refresh-only
terraform output -raw env_sh > ~/isucon14/env.sh
```

- 不要になったら、まとめて消します。

```bash
terraform destroy
```

- AMI にはセキュリティ更新が入りません。長いあいだ起動したままにしません。

| 期間 | 対応 |
| --- | --- |
| 数日〜数週間 | インスタンス停止（EBS のみ課金） |
| しばらく使わない | `terraform destroy` |

?> state バケットは `terraform destroy` では消えません。不要なら `aws s3 rb --force` で消します。
